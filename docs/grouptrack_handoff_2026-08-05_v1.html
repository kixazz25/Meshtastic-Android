3 · The queue was deleting its own successes

markComplete() branched on entry.refreshMode and silently removed the entry — no status, no stamp, no row. But refreshMode is also the REPLACE-TILES flag, and both of the day's Google corridor runs logged replace=true:

08:31:29  Corridor complete: CORR SAT downloaded=561 failed=0
08:47:04  Corridor complete: CORR SAT downloaded=681 failed=0

⛔ Both flawless. Neither visible. markFailed does not take that path, so the only download entries that ever survived were the ones that FAILED — which is why 08-02's "CORR SAT failed" was the only artifact left to reason from.

⭐ THE PRINCIPLE: the queue is the RECORD. Deleting rows to reduce clutter destroys evidence permanently; filtering hides it reversibly. Display concerns do not mutate state.

⚠ Still owed: the flag is overloaded — split isRefreshCell from replaceTiles. The schema comment at :442-444 already forbids the conflation; markComplete was the drift.

6 · Method notes worth keeping

  • ⭐ Read the HEAD of a stack trace before theorising. The root cause sat at frame 99 of a trace present in every capture from 09:00. The exception type was one line above it. Nobody read up until the afternoon.
  • ⭐ Filter the FILE, not the stream. adb logcat -d > file then grep. A bad pattern on a live stream is indistinguishable from a silent app — and Ctrl-C does not reach adb.exe in Git-Bash, so the redirect stops advancing while the prompt looks stuck.
  • ⭐ A negative grep is only as good as its pattern. Twice today a scan reported "clean" when it could not have matched what was there (log tags held in TAG constants; a range inside a <script src> whose inline body never executes).
  • ⭐⭐ Convoy is the reference implementation; divergence is a defect until proven intentional. Four times this week convoy had a fix the planner did not. Three are now closed; the reseed gate is the one legitimate difference.
  • ⚠⚠ PATCH VERIFIERS MUST DERIVE THEIR EXPECTATIONS, NOT ASSERT THEM. Five rollbacks today were the verifier, never the change: brace counts including comment text, a global string check catching an untouched block, an identifier matching the patch's own explanatory comment, and twice a hand-counted marker total. The guards behaved correctly every time — they refused writes they could not prove and left the tree clean — but each cost a re-run.
  • ⛔ An --apply whose output was never read is NOT applied. CORRIDORQUERY was recorded as landed and was not; it surfaced two patches later as an unresolved reference. git diff --stat is the authoritative answer to what is really in the tree.
