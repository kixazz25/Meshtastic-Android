⛔⛔ Both GPX import paths were dead

The in-app Downloads scan returned an EMPTY LIST — not an error — with a folder full of files. ⚠ The worst kind of failure: it looks like a correct answer. And the manifest route went with it.

⛔ So there was no way to import a GPX at all — and the Quick Start and manual both tell a new rider to import their tracks BEFORE building routes. The first instruction in the product was one the app could not carry out.

⭐ The rule that shaped the fix

Confirmed on device: an app may WRITE to Downloads freely; READING what another app put there needs permission. Export never broke. ⭐ Only import was broken, and the picker IS the permission — the rider's selection is the grant.

What was built

  • OpenMultipleDocuments, GPX/KML filtered, ⚠ with a */* fallback because GPX is frequently reported as octet-stream.
  • Each selection copied into app-private staging, size-verified, original deleted — all while the grant is live. ⭐ By the time the import runs the URIs are finished with.
  • ⛔ importGpxAllArtifacts untouched. It takes a File, so the file just has to be somewhere the app owns.
  • Staging cleared every run. The picker opens itself.

✅ 90 tracks imported and displaying, originals deleted.

⚠ MULTI-SELECT NEEDS A LONG-PRESS. Android's convention, not a bug — a plain tap selects one and returns. ⭐ Now in all three rider docs, because nobody would guess it.

⛔ Documents/GroupTrack kept coming back

MapStateStore.kt:33 calls GroupTrackStorage.dir("state"), and MapStateStore is an object singleton with no Context anywhere — the 09-11 handoff named it. So internalBase() returned null and the public fallback fired, creating a folder in shared storage the app could barely reach.

⛔ MISSED TWICE. 09-11 wrote it up as "the real problem of the next session" and the day went into the conversion. 09-13's CONVFIX primed the Context inside the conversion, which fixed the migration path only — ⚠ a fresh install skips the conversion entirely.

✅ One line in Application.onCreate, the only place that runs before every caller. ⭐ Convoy code was already in that function, so the upstream-file objection was smaller than it looked.

⭐ The fallback itself was left alone, deliberately — changing the failure behaviour of every accessor is a different job with its own risk.

The field version

  • Storage hardcoded internal. ⛔ The prompt was skipped on some launches — rendered and dismissed before input — leaving the mode unset and the app writing external. ⭐ Nothing chooses now, so nothing can fail to choose. External stays in the code, one line away.
  • Renames became deletes, same position. Documents/maps removed at the end.
  • ⭐ A fresh install skips the conversion entirely. Fred: "I do not want to scare 100 new users for 10 testers" — the migration is a courtesy for the ten. Detected by firstInstallTime == lastUpdateTime, a fact the system records. ⛔ Location-permission detection was REJECTED: a rider with location off would look new and their data would be stranded silently.

⚠ Process — it cost real time today
