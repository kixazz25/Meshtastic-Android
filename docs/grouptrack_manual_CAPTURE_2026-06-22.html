GroupTrack V2.5 — User Manual
Screen-by-screen cookbook · Off-road convoy tracking & trail navigation · grouptrack.org
How this manual works. This is a cookbook, not a reference list — it follows what you actually do. Each screen lists where it’s reached from, what you do there, and what it leads to. This edition covers the V2.5 heart of the app: the two maps and everything that feeds them (trails, tracks, routes, waypoints, downloads) plus organizer radio setup. Account, dashboard, and ride-management screens are part of the Release 3.0 cloud rewrite and are not documented here. Screenshots are added per screen in a following revision (live device capture).

1. Maps, Trails & Tracks (the heart of V2.5)

The two maps and everything that feeds them. This is where V2.5’s big changes live — icon-driven Work with Artifacts, universal search, the unified artifact detail panel, and trail import.
The right-edge icon column — how you reach everything on a map.
Both maps share a vertical icon column on the right edge: a search icon (magnifying glass), a Work with Artifacts icon, and a ? help icon. Tapping the Work with Artifacts icon opens that panel expanded; collapsing the accordion closes it. The old always-on Work-with-Artifacts bar is gone — it’s an icon now. On the Planning (Map Viewer) map the panel has full editing and import; on the Convoy (live) map the same panel is display-only (no editing or import during live convoy operations).

Reached from: Dashboard / active ride

Header shows the tile source, QUEUES, and the zoom readout (N · Z##). Track direction is shown with pixel-spaced neon arrows along each track.

Universal search (both maps)

The search icon opens a single search across five modes — Area · Track · Route · Trail · Waypoint. Pick a mode, search, and tap a result to open the unified artifact detail panel for it. This one search replaces the older per-map, per-type search entry points.

The artifact detail panel + Carto Type

One detail panel serves every artifact, reached three ways: from a search result, from a SELECT/Edit list row, or by tapping an artifact on the map. It shows the artifact’s rider-facing details with a collapsible technical section, plus action buttons (rename, change type, delete, share/export, and FIT — recenter the map to the artifact). For trails it shows a Carto Type band — the trail’s classification (OHV / Road-Concurrent, Hiking & Biking, Hiking-Only, Paved Shared Use, and so on, or “Unspecified”), colored by its carto color. The same carto type now also appears in the map popup when you tap a trail line.

Artifact types

Trails
Toggle ON to display trail overlays from the spatial database, loaded dynamically for your current viewport. Trail lines draw in their classification colors (see the legend), with the same Carto Type shown in the detail panel and the map popup. Trails display at zoom 8+; zoom in to see them.
Tracks
Toggle ON to display your recorded GPS tracks from the spatial database, loaded by viewport like trails. Tracks appear as neon green (#39FF14) dashed lines, with pixel-spaced direction arrows. Tapping a track shows its name (from the GPX filename).
Waypoints
Toggle to display user-created waypoints. 10+ standard types: trailhead, fuel, gate, hazard, scenic viewpoint, water source, camp, parking, junction, rally, and others. Drop one by long-pressing the map on empty ground (not on a vehicle marker) — a type picker opens.
Routes
Toggle to display saved routes from the spatial database, the same viewport-aware way as trails and tracks. Build a route with “+ ROUTE” (see “Creating a Route”). Routes display as magenta lines.

The trail color legend

A trail’s classification is encoded as a CartoCode (the leading digit of its type label), and trail lines on the map draw in that color:
OHV / Road-Concurrent — blue
Hiking & Biking — orange
Hiking-Only — yellow
Biking-Only — purple
Paved / other / unclassified — cyan
The Carto Type also appears in the artifact detail panel and in the trail’s map popup when you tap a trail line.

On the Planning Map a compact color legend sits in the corner. It starts collapsed as a small handle — tap it to expand the color key, tap the header to collapse it, and drag it anywhere on the screen to move it out of the way of a trail you’re examining.

SELECT / Edit and the three-state control

SELECT/Edit opens the artifact list for a type, scoped to the current view: a checkbox per item, Select All / Deselect All, and per-item actions. Each type also has a three-state display control — ON (show all in view), OFF (hide), and SELECTED (show only the items you checked). Each map remembers its own display selections independently: what you pick on the Convoy map no longer carries over to the Planning map.

FIT — recenter to an artifact

FIT (in the artifact detail panel) recenters and zooms the map to frame the selected artifact with a small margin, and keeps it selected. Use it to jump straight to a trail, track, route, or waypoint you’ve found in search or the list.

Creating a Route (early access)

  • Open the map (Convoy or Planning) and open Work with Artifacts, then tap “+ ROUTE”. The Route+ toolbar appears.
  • Tap “New”. A “Name this route” box appears with a suggested name — accept it or type your own — then tap “Start”.
  • Tap “Add” (it turns green), then tap the map to drop each point. Each point snaps to the nearest trail or track if one is close by, so your route follows established paths; tap away from any trail to place a free point exactly where you tapped. A magenta line connects your points in order.
  • Use “Undo” to remove the most recent point. Pan and zoom freely between taps to reposition the map.
  • Tap “Save” to store the route. It is saved on your device, redraws on the map in magenta, and appears in Work with Artifacts → Routes under the name you gave it. Tap “Discard” to leave without saving.
  • To move the Route+ toolbar around the map, the panel must be expanded (accordion open). Drag the grip handle in the header to reposition; when collapsed, tapping the header expands it rather than moving it.
Routes display in magenta. Saved routes load from the spatial database the same viewport-aware way as trails and tracks. Saving a half-finished route to resume later (“In Progress”), editing a saved route’s geometry, and the Draw and Suggest methods are coming in upcoming updates.

Import Artifacts & RESYNC TRACKS

  • Open Work with Artifacts and choose Import; pick your GPX file (the picker opens your device storage). Large files are processed one track at a time, so even big exports import without crashing.
  • When it finishes, a recap shows “X new / Y already in library.” New tracks draw on the map immediately. (If the artifact list looks empty, leave the screen and return — known refresh gap; the data is saved.)
  • Duplicates are identified by shape (geometry), not name: re-importing the same file is safe and shows “0 new / N already in library.”
  • RESYNC TRACKS recovers device track files that aren’t in the database (e.g. after an update): it scans my_tracks/ and adds any track not already saved. Run it again to confirm — a second run should add 0.
  • Tracks only, this build: importing a GPX brings in its tracks; waypoints and routes inside the file are skipped for now (separate import coming). The list caps at 200 shown — larger libraries are paged in a later build.

Trail & track display

When you open the Planning Map, GroupTrack scans your my_tracks/ directory and syncs any new GPX files into the spatial database in the background (it doesn’t block the map). Files already in the database are skipped. As you pan and zoom, the track query updates automatically (400 ms debounce) so only visible tracks load — instant response even with large libraries.

The current release includes trail data for the Utah / northern-Arizona corridor. Additional regional datasets will be downloadable in future updates through the Trail Source Manager. Trails load by viewport using bounding-box indexing; below zoom 8 they are hidden for readability.
Trail Sources
Reached from: Map Viewer → Work with Artifacts → IMPORT TRAILS
Browse approved trail sources and import them. The screen opens on Select Source — pick a source (e.g. UGRC Utah Trails), VALIDATE, then IMPORT TRAILS to download its trails (and any trailhead waypoints). A live recap counts records as they process (processed · new · dupes · aliased · already-imported). Already-imported sources show a green check but remain selectable — re-select one and run it again to reprocess it (refreshes trail classification / carto data on the existing trails without changing geometry). A separate By Area method imports the sources overlapping an area you draw on the map. After importing, close & reopen the app, then zoom in to see the trails.
Leads to: Back to Map Viewer with trails imported / updated

2. Offline Maps & Downloads

Pull map tiles for offline use and manage the download queue.
Download queue. The QUEUES button on both maps opens the queue management panel showing active, queued, and completed downloads. Controls: Hold (pause processing), Resume, Cancel Entry (remove one), and Cancel All (stop and clear). Transfer concurrency is settable (default 4, max 6). The controls are functional in the backend; the live-data queue panel UI is being wired in the next update.

Appendix — V2.5 Feature Status

Working now

  • Trail lazy-load from the spatial database (viewport queries); carto classification in detail panel + map popup
  • Track lazy-load from the spatial database with GPX sync; neon direction arrows
  • Work with Artifacts — icon-driven panel: display toggles, SELECT/Edit list, import
  • Universal search (both maps): Area · Track · Route · Trail · Waypoint
  • One unified artifact detail panel — reached from search, list row, or map artifact-tap; Carto Type band; FIT
  • Per-type SELECT/Edit list (checkboxes, Select All/Deselect All); per-map independent display selections
  • Viewport persistence (each map restores its last view + selection)
  • Trail Sources: Select-Source & By-Area methods; imported sources re-selectable for reprocess; live import recap; carto refresh on reprocess
  • Route creation — point-to-point with snap-to-trail/track, name, save (early access)
  • Waypoint creation — long-press on the map → type picker
  • Tile download system; expanded tile source catalog (16 sources); API key management; settable transfer concurrency (4–6)
  • Spatial database architecture + schema migration; minimum zoom 8
  • Queue management backend (hold, resume, cancel, cancel all)
  • Convoy “?” help button (opens this manual / release notes)

In progress

  • “In Progress” route drafts — save a half-finished route to resume later
  • Route Draw and Suggest methods (Point method is live)
  • Editing a saved route’s geometry; renaming from the Routes list
  • GPX import for waypoints and routes (tracks import is live)
  • Queue panel UI wired to live data
  • Waypoint / Route lazy-load from the spatial database (display)
  • Track survey on stop (rate + share)

Coming in Release 3.0 / later

  • Account, Dashboard, and Ride management — cloud rewrite
  • Cloud sync of local artifacts to a web account (premium)
  • iPad / iOS companion app; map heading-up rotation
  • National trail model with multi-state downloads
  • Organization services tier; database backup and recovery
