3. BUILD 2 — snap-on-tap (the next patch)
----------------------------------------------------------------
GOAL: tapped points snap to nearest trail (trail-first) or track (fallback)
within 30m, instead of free-placing raw coordinates.

TWO patches (line-ending split, same as Build 1):
  - ConvoyScreen.kt = LF        (onMapTap ~line 524)
  - ConvoyMapViewerScreen.kt = CRLF  (onMapTap ~line 478)

In EACH onMapTap handler, REPLACE:
    RouteManager.addVertex(RouteManager.freeVertex(lat, lon))
WITH (off main thread; viewport bounds already retained as
lastViewportSouth/West/North/East — ConvoyScreen 200-203, viewer 116-119):
    // query the on-screen trail/track set, snap, fall back to free
    kotlinx.coroutines.MainScope().launch {
        val v = kotlinx.coroutines.withContext(kotlinx.coroutines.Dispatchers.IO) {
            SpatialDbManager.init(context)
            val trails = SpatialDbManager.queryTrailsByViewport(
                lastViewportSouth, lastViewportWest, lastViewportNorth, lastViewportEast)
            val tracks = SpatialDbManager.queryTracksByViewport(
                lastViewportSouth, lastViewportWest, lastViewportNorth, lastViewportEast)
            val s = RouteManager.snap(lat, lon, trails, tracks, 30.0)
            if (s != null) RouteManager.snapToVertex(s) else RouteManager.freeVertex(lat, lon)
        }
        RouteManager.addVertex(v)
        val pts = RouteManager.routeVertices().joinToString(",", "[", "]") { "[${it.lat},${it.lon}]" }
        webViewRef<.value?|?>.evaluateJavascript("drawBuildLine('" + pts + "')", null)
    }
  NOTE the webViewRef difference: ConvoyScreen uses webViewRef.value? ;
  ConvoyMapViewerScreen uses webViewRef? .

  CAUTION: the existing handler already does the addVertex + drawBuildLine
  synchronously inside Handler(Looper.getMainLooper()).post{...}. Build 2 moves
  the snap query to a background coroutine. Keep the drawBuildLine on the main
  thread after addVertex. Re-read the exact current block before patching
  (Build 1 did not touch onMapTap, so it should be unchanged from the reads in
  this session's transcript).

ALSO in the same Build 2 patch (ConvoyRouteToolbar.kt, LF):
