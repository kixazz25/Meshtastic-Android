E3. ROUTE LIFECYCLE — SETTLED MODEL (Item 1 — ready to build)

Full spec: RouteLifecycle_SETTLED_DESIGN_2026-06-05. Reflects all 2026-06-05 simplifications.
Core rules: R1 Either/or — a route is EITHER an in-progress draft (JSON) OR a completed DB row, never both; graduation writes the row + deletes the draft. R2 Identity — in-progress identity = the typed NAME (set at New); route id assigned ONLY at graduation under DB dedup rules. R3 Save exits — every save EXITS route mode; to continue editing, Save In Progress then RE-SELECT from the In-Progress list. NO mid-session "save & continue", NO in-place state promotion. R4 State fixed at launch — New ⇒ NEW whole session; Select In-Progress ⇒ RESUMED whole session. The entry row is the launch fork that sets the state the adaptive screens read. R5 Writes minimal — only create-draft, overwrite-draft, insertRoute(+delete-draft), delete-draft. Roll-back / discard-new / cancel NEVER write. R6 Both maps — ConvoyScreen (LF) + ConvoyMapViewerScreen (CRLF), shared RouteManager; toolbar CRLF; cat -A before every patch. R7 Vertices not wkt — draft stores the full vertex chain; wkt/bbox derived at graduation (resumed draft graduates through the IDENTICAL completed-save path).
Save/Discard placement: on the COLLAPSED title bar (one-tap access, no real-estate cost) AND in the expanded panel. Each is ONE entry point opening an adaptive SCREEN; choices driven by fixed launch state.
Adaptive SAVE screen — NEW: [Save completed (≥2 pts, LIVE)] · [Save in-progress → writeDraft, exit (SOON)] · [Cancel]. RESUMED: [Graduate (+deleteDraft) (SOON)] · [Save with changes → overwriteDraft, exit (SOON)] · [Cancel]. Adaptive DISCARD screen — NEW: [Discard & exit (LIVE, no write)] · [Keep building]. RESUMED: [Roll back = reload unchanged draft, no write (SOON)] · [Delete in-progress = deleteDraft (SOON)] · [Keep building].

E4. WRITE-FUNCTION DATA CONTRACT

Completed-save consumes the RouteManager VERTEX chain. Vertex: lat, lon, lineId(String?), lineType(String?), segmentIndex(-1 free), t(0..1), snapped(Bool). Completed DB row stores ONLY wkt+bbox+name. DRAFT JSON stores the FULL vertex list (resume = true editing), NOT wkt. RESUME = parse→addVertex→drawBuildLine. GRADUATE = Build-1 save path + delete draft. A route is EITHER a draft-file OR a DB-row. Full spec: RouteWriteFunction_DataContract_2026-06-04.

E5. SHARED TABLE RULE

Tracks + routes share ONE table with a TYPE field (TRACK/ROUTE). insertRoute writes type=ROUTE; route dedup rides the same geom_hash/UNIQUE machinery as tracks (§K add-core bypass). Convert-to-route = reversible type flip; source_track_id links a converted track to its route. Route delete BLOCKED if type=ROUTE and assigned to an active ride with enrollments (V3.0 concern, not 2.5).

P. Data Protection — backup / journal / rollback (deferred V2.5 schema spec)
Deferred (schema-hardening subsystem, not snap-2). Full spec: GroupTrack_V25_DataProtection_v1 (archived). Three layers on grouptrack_user.spatialite: (1) Backup — auto on launch + before destructive ops; last 5 retained; /Documents/GroupTrack/data/backups/. (2) Change journal — every INSERT/UPDATE/DELETE on user tables, before+after as JSON, geometry as WKT, 12 triggers, 30-day retention. (3) Rollback — single-op undo, transaction rollback, point-in-time; creates backup first. Relevance to routes: when route create/edit/delete is journaled, before/after stores geometry as WKT (matches the write-contract's vertex→wkt derivation). NOT journaled: trail data (re-downloadable), transfer queue. Rules 23-25.
