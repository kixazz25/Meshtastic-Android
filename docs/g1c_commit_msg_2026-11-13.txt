2.7e parses with org.json (LENIENT); the port parses with GtOrgJson over kotlinx
(STRICT), whose own header says: "NOT REPRODUCED ... comments, single quotes,
unquoted keys, '='/';' separators, and text after the first value. Android
accepts those; [parse] throws (the golden run marks them EXPECTED)." Three
fixtures feed exactly those, two keys each. The FIRST run reported 58 SAME / 6

This is the G2g GtConfigs precedent.

  UNREACHABLE IN PRACTICE: GtMapSpec reads context.assets.open("map_sources.json")

  or unquoted keys. It is NOT the user-editable external map_sources.json that
  MapSourceManager.externalJsonFile() reads; that file never reaches this code.
  The TileJSON comes from OpenFreeMap, serving valid JSON.

  AND IT IS STILL TESTED AS HARD. Marking a divergence expected must never mean
  testing it less. The harness records the base key as EXPECTED and ALSO emits
  "<key>|newonly" with the port's own answer, so the iPad still compares NEW
  against NEW on those fixtures -- which is why the iPad reports 64, not 58.
  A staleness guard writes "# G1C-NOTE ... is STALE" if an expected key ever
  comes back SAME, because that is how an expected-diff list rots into a
  permanent excuse.

TWO WARTS REPRODUCED ON PURPOSE
  The cache: 2.7e holds the resolved template in a @Volatile var with NO
  invalidation, so a mid-session re-version is ignored until the process

ALSO IN THIS COMMIT -- G1b, AND THE RULE IT PRODUCED (living master).

G1b (TileCodec, 66 lines) is SKIPPED, not ported. It was inventoried as "the
first declared SOCKET in step 17 -- a seam contract, not a port"; it is neither.
There is no platform codec work left to declare a seam for, because nothing
re-encodes any more: TileCodec is V2.6a, built for raster satellite/topo
imagery, and both live producers pass role "overlay" so encode() returns at its
first line. VectorTiles -> pbf (protobuf; re-encoding would corrupt it);
ElevationTiles -> png (the pixel values ARE the heights, so lossy re-encoding
would put spikes and pits in the 3D terrain). The only role:'base' entries left
in map_sources.json are google-hybrid and a custom template -- the pre-vector
raster sources, whose store has been empty since the conversion.
  Where used: ONE call site (MBTilesStore:156) plus one doc comment.
  compressWebp, BASE_QUALITY and OVERLAY_QUALITY have ZERO external references.
  A Q4 catch inside the dead file: the early return makes OVERLAY_QUALITY unused
  and the whole WEBP_LOSSLESS arm unreachable, while the header still documents
  "OVERLAY -> LOSSLESS WebP", which the code stopped doing at [V2.6a-Q95-PASS].
  WebP IS still live on the READ side -- the MAP's HTML, not the manual's:
  GroupTrackScreen:1148/1162/1175 serve image/webp (already cleanup C2). The

M2 -- SKIP, DON'T REMOVE. Two decisions that were being run together:

  REMOVE  the Android code is deleted. A change to the shipping app, so it

  This supersedes the earlier "DELETE rather than PORT" wording used for G1g.
  G1g is SKIPPED: not ported, not yet deleted.

  WHY A SKIP IS PROVABLY SAFE: code not executed is by definition the same result
  under the new code. Unexecuted code contributes nothing observable, so omitting
  it leaves behaviour identical BY CONSTRUCTION. Consequence: a skip needs NO
  certification run -- its evidence is REACHABILITY. And certifying unreachable
  code is vacuous: 0 DIFF because neither side runs, so the pass carries no
  information. That is why "it certified clean" can never be the reason a member
  belongs in the port.
  THE ONE CAVEAT: the whole weight then rests on the reachability evidence being
  right, and on 11-13 three reachability calls were wrong in one hour, all from
  greps that excluded the declaring file. The argument is sound; the input needs
  the care. Hence M1's five questions, by FIELD and by FUNCTION, never filtering
  out the declaring file.
