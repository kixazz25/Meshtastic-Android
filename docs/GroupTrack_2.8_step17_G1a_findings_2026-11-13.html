5. The certification

148 keys — 11 MAXSLOT (every slot, mixed case, trailing space: uppercase() is in the path), 5 MAXSRC (proving sourceName is ignored identically), 32 ZRANGE, 96 CALC, 4 URL.

Two deliberate departures from G2f

⭐ Order is COMPARED, not sorted away — the opposite of G2f's rule 3. 2.7e builds tiles with mutableListOf and nested for (z) for (x) for (y), so order is fixed by the source, not by a hash or the filesystem. It is part of the behaviour and a reordering would be a real defect. G2f sorted because its collections came from set iteration and listFiles(); nothing here does.

⚠ Mercator edges are in the sweep on purpose — at 89.999° tan(rad) runs away and 2.7e clamps nothing. Both sides must run away identically: faithfulness, not correctness. A defect both sides reproduce is a PASS.

Boxes are deliberately tiny (0.01°) so CALC stays a value comparison and not a memory test — enumerating a state-sized box is the millions-of-tiles problem that created zoomRanges (REMOVEAREA-2026-11-03).

lon2tile/lat2tile are not under test: certified at 16a as MATHTILE, 0 DIFF across 1,938,346 values. OLD calls 2.7e's own, NEW calls GtTileMath's. Shared ground is what makes a DIFF here attributable to G1a's members alone.

7. Port fidelity defect found and fixed

2.7e is maxZoomForSource(sourceName: String): Int = ConvoyConfig.DOWNLOAD_ZOOM — it takes sourceName and ignores it, a [V2.6b-NO-ZOOM-CAP] leftover. The port had replaced the parameter with downloadZoom rather than adding to it. 16b's rule is that app state becomes an additional parameter; the original signature is still the thing being certified. Corrected to maxZoomForSource(sourceName, downloadZoom), with the call site mirroring 2.7e's maxZoomForSource(sourceName). Behaviour is unchanged on both sides — the point is shape, so OLD and NEW can be compared argument for argument.

Found by reading the OLD source to build the CertOld copy, which is what that exercise is for.
