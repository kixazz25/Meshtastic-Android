⭐⭐ The fallback lock — the find of the day

Symptom: first launch of the day, three ESRI sources instead of fifteen, Select Source empty, the rider's slots ignored. Only killing the app cleared it.

⛔ loadFallback() ended with initialized = true. init() begins if (initialized) return. One line of bookkeeping made a transient failure permanent for the process.

⭐ And ensureInit() does not FIND fallback data, it INSTALLS it — a reader arriving before init() calls loadFallback() itself. Cold start is when that race loses: no warm process, no page cache, and workers resuming from a previous session touch the manager before any screen renders.

⭐⭐ THE DURABLE LESSON: a failure path that records itself as a success blocks its own recovery. Fred: "we recorded a failure so well we didn't let it recover naturally."

⚠ NOT YET VERIFIED. Needs a cold start, first launch of the day, before touching either device:

⛔⛔ The palette — three copies of the truth

⭐⭐ Fred's diagnosis: "we were not defaulting to the shipped json, which was correct. we were not defaulting to the user values, which were correct to him. we were defaulting to a 3 month old version of the truth."

The palette exists in THREE places: map_keys_defaults.json (shipped, current), the rider's map_keys.json (their tuning), and a hardcoded TRAIL_STYLE literal in each map HTML — a stale snapshot. ⛔ The HTML copy is what draws, and setTrailStyles is called from ONE place per screen: the key panel's onStyleChanged. So a rider's colours reach the map only when they edit something.

⚠ The two HTML copies have already drifted: the planner carries rider, the convoy map does not.

🔴 TOMORROW'S DESIGN — settled, not built

  • One source: the rider's map_keys.json. The asset is a seed, not a runtime default.
  • installDefaults runs EVERY launch, gated on CATEGORY existence rather than FILE existence (Fred): no file → write the asset; file missing a category → add it with shipped values; complete → do nothing. ⚠ Never overwrite what the rider set. Folds together with mergeShippedCategories, which already does half the job.
  • Then empty TRAIL_STYLE in both map files.

⛔ EMPTYING THE HTML ALONE IS NOT SAFE. With no push at load, every trail falls through to the unknown fallback — cyan, weight 2 — until a rider opens the key panel. Both halves ship together or not at all.
