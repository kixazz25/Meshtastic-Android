The GPX round trip passes. Export a route on one device, import on the other, and the narrative and recipe both arrive. That was the one thing in 2.6g the checklist said had never been tested — and it found four separate defects in one chain, none of them visible to code inspection.

Also in: rider-trail delete, the ride map's route tap, layer ordering, the key-legend row, and a second housekeeping entry point.

⭐ The round trip — four defects, each hiding the next

  1. The export never wrote the payload. parseGpxRoutes has looked for <grouptrack:notes> since 08-29 and prefers it over <desc>. Nothing ever wrote it. ⚠ The parser's own comment says "our own extensions payload carries the recipe home" — present tense, about a writer that did not exist.
  2. The import never stored the notes. insertRoute took the geometry and dropped route.description on the floor. 08-29 fixed the reader and left the writer.
  3. ⭐ The import wrapped the payload as a headline. Mine — and correct right up until the export started working, because description had only ever held plain prose.
  4. Nothing decoded the XML entities. The payload arrived as {&quot;generated&quot;…} and became gibberish in the narrative panel. ⚠ A regex is not an XML parser.

⚠ &amp; is decoded LAST. First, and a literal &amp;quot; becomes a quote — silently corrupting text that legitimately contained an escaped entity.

⛔⛔ How a half-finished item read as open for six weeks

Fred: "how do we get to this point in release planning to find things that we just left incomplete?"

The checklist was right and I overrode it. This morning I read two greps, found the export fixed and the parser reading <desc>, and reported the item done and the checklist stale — then argued the rest of the list probably was too. I never checked whether the parsed value was stored. It was not, one function away from where I was looking.

⛔ "THE CODE EXISTS" IS NOT "THE PATH WORKS."

The rules that come out of it

  • ⭐ Trust the record when it says open. Prove it end to end, then strike it. Never reason that it must have been done.
  • ⭐ Keep the checklist current as work lands, in the session it lands. Amending a line costs seconds; re-deriving it six weeks later cost a day.
  • ⭐ A line must be able to say PARTIAL. "export done, import not" had no home, and that is the shape of every defect found today.
  • ⭐ Only open items belong on the checklist — already the stated rule.
  • ⚠ Some items cannot be certified alone. Export proves nothing until something imports.

⭐ The second housekeeping entry point

run() checks its marker first and returns, so nothing in it fires on a normal launch. everyLaunch(ctx) has no marker and runs every time.

⭐⭐ NO MARKER, AND NONE IS WANTED. Fred: "we are responsible for removing one time launch code from the next release." ⚠ REMOVE IT WHEN THE NEXT RELEASE IS CUT.

Rules for anything put in it: cheap, idempotent, non-destructive, never throws. ⚠ Called AFTER the gate resolves — it touches shared storage.

⛔ Four anchor failures today, all the same mistake

Every one was an anchor built by eye from terminal output instead of cat -A, and every one was caught by its guard rather than by me: a miscounted dash run, and three missed blank lines — one of which broke the build for twenty minutes.

⭐ THE FIX IS NOT A BETTER COUNT — stop anchoring on decorated lines. Plain ASCII prose, or locate the target structurally. ⚠ And an anchor starting at a declaration says nothing about what is attached ABOVE it.
