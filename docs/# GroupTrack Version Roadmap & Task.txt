## V2.4 GroupTrack Foundation

### Primary Objectives

**1. Stabilize Map Storage Forever**
- **Problem:** Maps scattered across debug/release locations causing ongoing issues
- **Solution:** Clean slate approach - lose existing maps, create permanent structure
- **Result:** `/Android/data/com.grouptrack.android/files/maps/` - never moves again

**2. Enable Solo Navigation (Radio-Free Evaluation)**
- **Problem:** Users must invest in radios before evaluating platform
- **Solution:** Phone-only tracking, viewing, navigation capabilities
- **Result:** Compete with Gaia/onX, expand testing pool, enable cloud radio strategy

**3. Improve Convoy Operations**
- **Problem:** Lead cart assignment automation fails frequently
- **Solution:** Manual assignment with broadcast + click-to-assign backup
- **Result:** Reliable lead cart management for convoy coordination

### Detailed Tasks

#### Storage Migration & Cleanup
**Duration:** 1-2 days
- **Search and remove** all existing tile locations (debug + release)
- **Create new structure:** `/files/maps/SAT/`, `/files/maps/TOPO/`, `/files/maps/HYB/`, `/files/maps/TOPO+/`
- **Clean architecture:** No legacy data, optimal organization for future versions
- **Testing:** Verify clean install, tile download, storage access

#### Lead Cart Assignment Overhaul  
**Duration:** 2-3 days
- **Remove automated assignment logic** (source of current issues)
- **Add manual "I am lead cart" UI** with broadcast to all participants
- **Add click-to-assign functionality** for corrections/changes
- **Special case:** Standalone Android (no radio) auto-assigns itself as lead with self-tracking
- **UI Integration:** Convoy screen controls, visual feedback, status confirmation

#### Trail Overlay Integration
**Duration:** 3-4 days
- **UGRC/USFS trail data integration** (GeoJSON format)
- **SAT HYBRID source:** Current SAT + trail overlays
- **TOPO with trails:** Current TOPO + same trail overlays  
- **User controls:** Trail visibility toggle, overlay management
- **Performance:** Optimize rendering for large trail datasets
- **Testing:** Utah trails visibility and accuracy validation

#### KML/GPX Track Viewing Map
**Duration:** 2-3 days
- **New map screen:** Copy convoy map foundation, remove convoy-specific overlays
- **Track selection UI:** Choose from "My tracks" directory
- **Multi-track display:** Show multiple GPX/KML files simultaneously
- **Track styling:** Colors, line weights, visibility controls
- **Integration:** Leverage existing GPX/KML parsing if available

#### Map Source Configuration
**Duration:** 1 day
- **Retain SAT** as current satellite imagery
- **Add SAT HYBRID** (SAT + UGRC/USFS trails)
- **Enhance TOPO** (current topo + UGRC/USFS trails)
- **Keep TOPO+** as current enhanced topographic
- **User selection:** Source picker in map interface

### V2.4 Success Criteria
- ✅ Storage structure permanent (no more migrations ever)
- ✅ Solo tracking functional (phone-only navigation capability)
- ✅ Lead cart assignment reliable (manual selection working)
- ✅ Trail overlays visible (UGRC/USFS data rendering)
- ✅ Track viewing operational (post-activity validation)
- ✅ Clean GroupTrack branding (final separation from Meshtastic)

**V2.4 Total Effort:** 8-12 days development + testing

## V2.5 GroupTrack Map Manager

### Primary Objectives

**1. Independent Planning Map**
- **Purpose:** Route planning separate from convoy operations
- **Architecture:** Independent map instance, shared tile storage with V2.4
- **Access:** Services menu → Planning Map

**2. Advanced Route Creation**
- **Waypoint management:** Create, edit, categorize, library system
- **Route drawing:** Tap-to-place waypoints, connect with lines
- **Snap-to-trail feature:** Smart routing along UGRC/USFS trail data
- **Route types:** Loop, out-and-back, point-to-point planning

**3. Enhanced File Management**
- **GPX/KML import/export:** File picker integration, format validation
- **Route library:** Local storage, metadata management, organization
- **Share capabilities:** Export planned routes for distribution

### Detailed Tasks

#### Planning Map Architecture
**Duration:** 3-4 days
- **Independent map component:** Separate from ConvoyViewModel
- **Shared storage access:** Use V2.4 `/files/maps/` structure
- **Navigation integration:** Services menu → Planning Map route
- **State isolation:** No interference with convoy operations
- **UI Framework:** Full-screen map with planning-specific controls

#### Waypoint Management System
**Duration:** 4-5 days  
- **Waypoint creation:** Long press map → create waypoint
- **Categorization:** Trailhead, staging, hazard, POI, custom types
- **Library management:** List view, search, edit, delete operations
- **Metadata:** Name, description, coordinates, type, creation date
- **Integration:** Waypoint picker for route creation

#### Route Planning Tools
**Duration:** 5-6 days
- **Route drawing:** Tap waypoints to create route segments
- **Snap-to-trail:** Automatically follow UGRC/USFS trail data when possible
- **Route editing:** Insert waypoints, delete segments, modify paths
- **Route types:** Support loop, out-and-back, point-to-point planning
- **Validation:** Check route connectivity, estimate distance/elevation

#### Advanced File Operations
**Duration:** 3-4 days
- **Enhanced import:** ACTION_OPEN_DOCUMENT integration, format validation
- **Export options:** GPX, KML formats with full metadata
- **Batch operations:** Import/export multiple files, folder management
- **Route library:** Local organization, search, duplicate detection

#### Tile Management Enhancement
**Duration:** 2-3 days
- **Download progress tracking:** Visual feedback, pause/resume capability
- **Storage optimization:** Cleanup unused tiles, compression options
- **Preload planning:** Download tiles for planned route corridors
- **User preferences:** Tile source defaults, zoom level management

### V2.5 Success Criteria
- ✅ Planning Map independent and functional
- ✅ Waypoint library comprehensive (create, edit, organize)
- ✅ Route planning intuitive (snap-to-trail working)
- ✅ File management robust (import/export reliable)
- ✅ Tile optimization effective (storage management)

**V2.5 Total Effort:** 15-20 days development + testing

## V3.0 GroupTrack Service Integration

### Primary Objectives

**1. Online Service Platform**
- **Backend integration:** Expand PHP API to use full database schema
- **User accounts:** Complete profile management with location services
- **Service delivery:** Value-first approach (all features free initially)

**2. Ride Coordination Automation**
- **Map area integration:** V2.5 route planning → automatic ride boundaries
- **Participant tile delivery:** Automatic download of ride areas for participants
- **Trailhead integration:** V2.5 waypoints → ride trailhead selection

**3. Community Platform**
- **Content sharing:** Track library, community contributions, ratings
- **Social features:** Follow organizers, location-based discovery
- **Communication:** Real-time updates, notifications, messaging

## Implementation Dependencies & Risk Management

### Cross-Version Dependencies
**V2.4 → V2.5:** Stable storage required for advanced planning tools
**V2.5 → V3.0:** Route/waypoint data needed for automated ride coordination
**All versions:** Shared tile storage ensures no duplication or conflicts

### Risk Mitigation
**V2.4 storage migration:** Clean slate approach eliminates migration complexity
**V2.5 feature isolation:** Planning Map independence prevents convoy interference  
**V3.0 backend expansion:** Existing PHP patterns reduce implementation risk
**Shared architecture:** Common components reduce testing and maintenance overhead

### Success Metrics
**V2.4:** Storage stability + solo navigation capability + convoy improvements
**V2.5:** Planning tool completeness + file management + enhanced tile system
**V3.0:** Online service delivery + community engagement + automated coordination
