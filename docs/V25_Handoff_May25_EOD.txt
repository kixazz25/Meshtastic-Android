ARCHITECTURE — KEY DECISIONS
==========================================
[DECISION] selectedArtifactIds IS the JS filter
  Viewport handler filters query results by selectedIds
  before building GeoJSON. Checkbox updates set, triggers
  viewport refresh. Clean separation: Kotlin filters, JS
  renders whatever it receives.

[DECISION] Three-state toggle (planned, not yet implemented)
  Gray: OFF, nothing displayed
  Blue: ON, all items displayed
  Yellow: ON, SELECT filter active (partial display)

[DECISION] Dynamic list merge on zoom (planned)
  When viewport changes with SELECT active:
  - Keep existing checked/unchecked state
  - Add new items entering viewport as UNCHECKED
  - Selected items stay on map, new items don't auto-show
  - User decides what to add

[DECISION] Preload architecture
  onViewportChanged ALWAYS queries all 4 types. Data pushed
  to JS layers. Toggle = visibility only (show/hide). moveend
  always fires. JS update preserves visibility (wasVisible).

[DECISION] Trail duplicate name options (for cleanup)
  1. Group by name: "JEM Trail (12 segments)"
  2. DISTINCT query: collapse to unique names
  3. Alias system: rename/group under display name
  4. Append GPS coord: "JEM Trail (37.48, -113.32)"
