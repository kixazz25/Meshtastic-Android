3. The proposed sequence (by what step 18 needs first)

Step 18's acceptance (plan §11): the map opens on the iPad simulator as on Droid 1, with Droid 1's data, saved view and filter; then Droid 2's seed email imported on the iPad. So the order follows what the iPad needs to open the map, then what the screens need:

  1. 17-1 G2 storage, settings, startup — the iPad can find and open its files, settings and profile (the "where are my files" socket first; it removes most of the 124 Context uses).
  2. 17-2 G1 map store and sources — the iPad map draws from the same stores (the image decoder socket).
  3. 17-3 G4 the map-page interface — the display and route-draft code talks to either map page.
  4. 17-4 G3 trail rules and land — who may ride where, the same on both.
  5. 17-5 G5 pure ride logic — small, fast certs (golden values).
  6. 17-6 G6 exports and sharing — the seed email the step 18 acceptance imports.
  7. 17-7 G7 server and catalogs — sign-in, rides on AWS, the state catalog.
  8. 17-8 G9 the worker interfaces (the workers themselves stay Android).
  9. G8 ride runtime and group awareness — AFTER step 18–19, with the screens and a real iPad (Bluetooth + GPS; field test January, Utah). The two big splits (GroupTrackScreen, ConvoyViewModel) are done in this group.

Then 17b (the Droid 2 rebuild walk — the control), 17c, 18.

4. The process, per group (the method that took steps 10–16 through)

  1. Inventory the group — every file, every caller, every Android tie — to Fred before any port.
  2. Simulate on the Mac's real data where the group computes something (as tonight's 16c simulation: volumes, edge cases, what the cert will meet) — before any patch is applied (Fred 11-11 18:48).
  3. Port AS IS into grouptrack-shared — the platform rules (plan §18): GtMath, GtJava text, GtOrgJson, GtRx, GtGeom, sorted listings, Java collection order where it reaches a result. No behaviour change.
  4. iPad compile (compileKotlinIosSimulatorArm64) before every build.
  5. Certify: TEST-ONLY generated OLD copies (counted substitutions; any miss writes nothing), ONE shared runner, Droid OLD = NEW (0 DIFF), then the iPad = the Droid's report (0 DIFF, input fingerprints equal: "cross-device COMPARED") — on real data, nothing live touched.
  6. Switch: front doors; the files checked byte for byte against the certified ones before the switch (16d's check).
  7. Walk on Droid 1 the screens that use it; commit by explicit paths, no attribution lines; push.

Sockets (paths, settings, image decoding, GPS, Bluetooth, share / email, background work): a shared interface; Android wired to today's code unchanged; the iPad a placeholder until its turn. A socket is checked by a Droid walk, not a cert (there is no new logic in it).
