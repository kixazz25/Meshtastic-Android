=======================================================
PROBLEM 1: DOWNLOAD PANEL CHECKBOXES NOT HOLDING STATE
=======================================================

SYMPTOM:
  Tapping a checkbox (Tiles, Trails, etc.) appears to check it but
  it instantly reverts to unchecked. Cannot check any box. Cannot
  draw area (requires checked box). Cannot download tiles or trails.

ROOT CAUSE:
  The download panel (ConvoyDownloadPanel.kt) used internal
  `remember { mutableStateOf(false) }` for checkbox state. The panel
  is inside `if (showDownloadPanel)` in ConvoyMapViewerScreen. When
  ANY state in the parent composable changes, Compose may recreate
  the panel, resetting all `remember` state to defaults.

  This was ALWAYS happening but was invisible when defaults were
  `true` — resetting to "checked" looked correct. When we changed
  defaults to `false`, the reset became visible: check → reset to
  unchecked → appears broken.

FIX APPLIED (in overnight build):
  patch_v25_lift_panel_state_v1.py

  Lifted all checkbox state from ConvoyDownloadPanel (child) to
  ConvoyMapViewerScreen (parent):

  BEFORE (in ConvoyDownloadPanel.kt):
    var tilesChecked by remember { mutableStateOf(false) }  // RESETS on recompose

  AFTER (in ConvoyMapViewerScreen.kt):
    var panelTilesChecked by remember { mutableStateOf(false) }  // SURVIVES
    // passed as parameter to ConvoyDownloadPanel

  ConvoyDownloadPanel now receives checkbox state as parameters with
  callback lambdas (onTilesCheckedChange, etc.) instead of managing
  its own state. Parent state survives panel recomposition.

  Files modified:
    ConvoyMapViewerScreen.kt — added state vars + passed to panel
    ConvoyDownloadPanel.kt — changed to accept params, removed internal state

TEST:
  1. Planning Map → tap ↕ FAB → panel opens
  2. Tap "Download Tiles" checkbox → should stay checked
  3. Tap "Import Trails" checkbox → should stay checked
  4. Tap "Draw Area" → should be enabled (checkbox is checked)

TASK: LAZY LOAD TRAILS FROM SPATIAL DB
=======================================================

This is the #1 priority for May 21. All trail data is in the spatial
DB (49K UGRC Utah trails). The task is to display them on both maps
via viewport-based lazy loading.

ARCHITECTURE:
  1. JS viewport change → report bounds to Kotlin
  2. Kotlin queries SpatialDbManager → builds GeoJSON
  3. Kotlin injects GeoJSON via evaluateJavascript
  4. Leaflet renders trail layer on map

STEP 1: JS — Add viewport listener + updateTrails function
  Files: convoy_map.html AND grouptrack_map.html

  Add to both HTML files:
    // Trail layer
    var trailLayer = null;

    function updateTrails(geojsonStr) {
      if (trailLayer) map.removeLayer(trailLayer);
      var data = JSON.parse(geojsonStr);
      trailLayer = L.geoJSON(data, {
        style: function(feature) {
          var cc = feature.properties.CartoCode || 0;
          var color = cc == 4 ? '#FF6600' :   // OHV
                      cc == 1 ? '#22AA22' :   // Hiking
                      cc == 2 ? '#2288DD' :   // Hiking+Biking
                      cc == 5 ? '#DD8822' :   // Biking
                      '#888888';               // Other
          return { color: color, weight: 2, opacity: 0.7 };
        }
      }).addTo(map);
    }

    function clearTrails() {
      if (trailLayer) { map.removeLayer(trailLayer); trailLayer = null; }
    }

  Add viewport change listener (debounced):
    var trailDebounce = null;
    map.on('moveend', function() {
      if (trailDebounce) clearTimeout(trailDebounce);
      trailDebounce = setTimeout(function() {
        var b = map.getBounds();
        if (typeof Android !== 'undefined' && Android.onViewportChanged) {
          Android.onViewportChanged(
            b.getNorth(), b.getSouth(),
            b.getEast(), b.getWest(),
            map.getZoom()
          );
        }
      }, 300);
    });

STEP 2: Kotlin — Add JavascriptInterface for viewport
  Files: ConvoyScreen.kt AND ConvoyMapViewerScreen.kt

  Add to the WebView's addJavascriptInterface object:
    @JavascriptInterface
    fun onViewportChanged(north: Double, south: Double,
                          east: Double, west: Double, zoom: Int) {
      if (!trailsVisible) return  // respect display toggle
      android.os.Handler(android.os.Looper.getMainLooper()).post {
        scope.launch(Dispatchers.IO) {
          val geojson = SpatialDbManager.queryTrailsAsGeoJson(
            context, south, west, north, east
          )
          withContext(Dispatchers.Main) {
            webViewRef?.evaluateJavascript(
              "updateTrails('${geojson.replace("'", "\\'")}')", null
            )
          }
        }
      }
    }

STEP 3: SpatialDbManager — Query + GeoJSON builder
  File: SpatialDbManager.kt

  May already exist — check for:
    fun queryTrailsByViewport(south, west, north, east)
    fun buildTrailGeoJson(cursor)

  If not, create:
    fun queryTrailsAsGeoJson(context: Context,
        south: Double, west: Double,
        north: Double, east: Double): String {
      val db = getSpatialDb(context)
      // Query trails table where first coordinate is within bbox
      // Filter by CartoCode 1, 2, 4, 5 (hiking, biking, OHV)
      val cursor = db.rawQuery("""
        SELECT trail_id, geometry_json FROM trails
        WHERE min_lat <= ? AND max_lat >= ?
        AND min_lon <= ? AND max_lon >= ?
      """, arrayOf(north.toString(), south.toString(),
                   east.toString(), west.toString()))
      // Build FeatureCollection
      val sb = StringBuilder("{\"type\":\"FeatureCollection\",\"features\":[")
      var first = true
      while (cursor.moveToNext()) {
        if (!first) sb.append(",")
        first = false
        val geom = cursor.getString(1)
        sb.append("{\"type\":\"Feature\",\"geometry\":$geom,\"properties\":{}}")
      }
      cursor.close()
      sb.append("]}")
      return sb.toString()
    }

  NOTE: The trails table schema may need min_lat/max_lat/min_lon/max_lon
  columns for spatial indexing. Check current schema:
    grep "CREATE TABLE trails" app/src/main/assets/schema_extension_v1.sql

STEP 4: Wire Trails toggle to lazy load
  The Trails toggle on ConvoyDisplayPanel controls `trailsVisible`.
  When toggled ON: call onViewportChanged to load current viewport.
  When toggled OFF: call clearTrails() via evaluateJavascript.

  In the toggle handler:
    onTrailsToggle = {
      trailsVisible = !trailsVisible
      if (trailsVisible) {
        // Trigger initial load
        webViewRef?.evaluateJavascript("triggerViewportUpdate()", null)
      } else {
        webViewRef?.evaluateJavascript("clearTrails()", null)
      }
    }

  Add to JS: function triggerViewportUpdate() that fires the moveend
  handler manually.

STEP 5: Performance considerations
  - 49K trails is too many to send at once — limit by zoom level
  - At zoom < 10: don't load trails (too many, too small)
  - At zoom 10-14: load simplified/thinned trails
  - At zoom 14+: load full detail
  - Consider limiting to 2000 features per viewport update
  - GeoJSON string can be large — consider chunking if > 1MB
