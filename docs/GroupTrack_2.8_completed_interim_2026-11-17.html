⛔ The duplicate-record defect, and what it really was (TRACKROUTESEP-2026-11-17)

EVIDENCE: four routes admitted on 11-17 at 18:22Z; the simulation predicted all four reimport hashes character-for-character before the device database was pulled (gt_importsim_2026-11-17_v1.py). Live DB after: 27 routes, 27 distinct hashes, 0 shared; UNIQUE(geom_hash) present as sqlite_autoindex_routes_2. Fixed in d38a70333.

trackToRoute emitted its WKT with joinToString(", ") while every other writer (GtGeom.coords, RouteManager.buildWktAndBbox, RiderTrailWriter.buildGeometry) emits ",". Since geom_hash = sha256(WKT text), one space per coordinate pair is a different identity for identical ground, so UNIQUE(geom_hash) enforced "no duplicate spelling" and never saw the duplicate geometry. The dedupe was never broken; the WRITER disagreed with itself. This was an intermittent bug — it only fires on a track converted to a route and then reimported — which is why nine months of production and a certified file-I/O pass never caught it.

Two things it also exposed, both still open: the recap counters are documented as "tracks newly inserted" and the route block only does routeCount++, so routes and waypoints have never had honest insert accounting; and the select screen showing 25 of 27 is a bbox filter, not phantom rows.

⛔ TRIED AND REVERTED THE SAME DAY — canonicalising the hash (CANONREVERT-2026-11-17)

Recorded so it is not rebuilt. The first fix proposed canonicalising inside GtGeom.hash — and that was over-engineering a defect that lived in one caller. Fred stopped it with the right question: "what are we changing the hash that works?" Canonicalising changes identity semantics for all four spatial tables, drags in a convergence job and a corridor-tile re-key, and — decisively — skews 2.7e and 2.8 hashes apart, which would have destroyed Droid 2 as the oracle on the very night a reseed was planned. GtGeom.hash is back to wkt.encodeUtf8().sha256().hex(). GtGeom.Parsed.canonical() (written 11-09 for exactly this case) remains unused and correct to leave unused.

The durable rule: the hash was not wrong, so the hash was not the place to fix it. Shape-based duplicate detection is already parked as C28-26319 for after 2.8, "because it touches every import path".
