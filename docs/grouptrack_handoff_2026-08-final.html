⭐ The URLs are not in Kotlin — that is why the first greps found nothing

ConvoyConfig.kt:15 says it plainly: "TILE_SOURCES — reads from MapSourceManager (map_sources.json)." MapSourceManager.kt:90 reads url_template out of JSON. So grep lyrs= across app/src returns nothing and sends you looking in the wrong place. Asset: app/src/main/assets/map_sources.json.

Template: https://mt{s}.google.com/vt/lyrs=y&x={x}&y={y}&z={z}. Five sources use {s}: google-hybrid, -satellite, -roads, -terrain, cartodb-voyager. Everything else uses literal hostnames — which is why only the Google sources looked dead.

BUG 1 — download path

ConvoyTileDownloader.buildTileUrl substituted {z}/{x}/{y} and nothing else. {s} was handled nowhere — grep across all Kotlin returned zero hits. The literal string mt{s}.google.com went to DNS and every tile failed silently.

.replace("{s}", (((tile.x + tile.y) % 4 + 4) % 4).toString())   // SUBDOMAIN-2026-08-02

Added as the first replace. Double-modulo guards negative x at antimeridian wrap; % 4 gives mt0–mt3, deterministic per tile so a retry hits the same host.

BUG 2 — display path

Leaflet does expand {s} — but its default subdomain set is 'abc', so it requested mta/mtb/mtc.google.com, which do not exist. Neither map set a subdomains option.

subdomains: (url.indexOf('google.com') !== -1 ? '0123' : 'abc')   // SUBDOMAINS-2026-08-02

In both convoy_map.html (~:47) and grouptrack_map.html (~:111). Derived from the URL, not hardcoded — Google needs 0123, Carto needs abc.

⚠ The subdomains option is still missing on the overlay layers (convoy_map.html ~:71, grouptrack_map.html ~:138). Inert today; a subdomain'd overlay source would fail the same way.

4 · ⛔ The lesson of the week

THREE-FOR-THREE: every convoy rendering failure in this arc was instrumentation aborting a method before its real work

  1. ?: return inside a toast argument killed onPageFinished — no tile setup, no setTileUrl, no persisted-frame restore, no drawPersistedState
  2. evaluateJavascript / Toast on a @JavascriptInterface background thread killed onViewportChanged — no processViewport, so no artifacts drew
  3. The offline render failure, cleared by removing ten more toasts from the same file

All three landed in or around onPageFinished.

Instrumentation is not free, and on this codebase it has cost more than the bugs it was added to find. When adding a trace to an override or a bridge method, ask what happens if that line throws or returns.

⭐ The counter-example is 08-02's tap fix: using instrumentation that already existed found the defect in three taps with no new code at all. Read the logs before adding to them.

5 · Source configuration has no persistence layer — root cause found

ROOT CAUSENothing is putting Esri back. The choice was never saved.

Fred: "Something keeps placing Esri hybrid in slot 1 even after I replaced with Google."

XREF EVIDENCE (field_crossref_raw.txt): MapSourceManager has exactly two writes — :62 (dir.mkdirs()) and :248 (apiKeysFile().writeText). The API keys file is the only thing it persists. Slot fields are read-only: :113 slot, :114 source_id, :115 legacy_key.

DEVICE EVIDENCE: adb shell find /sdcard -name "map_sources.json" returns nothing. The external override anticipated at MapSourceManager.kt:66 does not exist.

⭐ One missing layer, three symptoms: slot 1 reverting to Esri · activeSourceKey resetting to SAT on every restart (declared = "SAT", in-memory only) · possibly the Google download abort itself.

⛔ It was built, then deliberately removed — and why matters

git log -S "externalJsonFile" returns exactly two commits:

  • 49bc8cecb — V2.5 Map Source Selection — ADDED it
  • 79251ae72 — 2026-05-21, "Fix tile download — read asset JSON only" — REMOVED it

Both halves went: the read-external-first-with-copy-on-first-run block, and the entire body of saveExternalJson() — replaced with // Disabled — asset is single source of truth. ⚠ The empty function still exists and is still called, silently doing nothing.

⭐⭐ Why it was removed vindicates the fix. The external file held the entire catalogue, URLs included — so a stale copy served stale URLs and broke tile downloads, which is exactly what that commit was fixing. Ripping it out was correct for a real bug.

⭐⭐ The architecture (Fred) — two structures, two functions

"There are two structures — the CATALOG which should be distributed, and the SLOT ASSIGNMENT of catalog to user's map slot. Two separate functions."

CATALOG = map_sources.json in assets. Sources, templates, layers, default_slots, versions. Distributed with the app, read-only, replaced every release. ⭐ This is what makes a URL correction reach existing users — the {s} fix lives in a template here. Had the catalogue been copied to user space on first run, no existing user would ever receive it.
SLOT ASSIGNMENT = which source_id occupies each user map slot, plus the active slot. User-owned, persisted, survives reinstall. Fred: "The slot assignment is a JSON that should exist in user space and be populated from default asset on install."

⛔ Do NOT restore 49bc8cecb as-was — that reintroduces the stale-URL bug. Persist only {slot, source_id, legacy_key} plus the active key, never the sources array. ⚠ Seed only when the user file is ABSENT — re-seeding on every install recreates the bug.

6 · Refresh is still on the bbox model and old segmentation

568 entries at 60–70K tiles each

Downloads cut over to corridors on 07-24. Refresh was never migrated — still bbox, still on the old gridCells instead of segmentCells. A map-source refresh enqueued 568 entries at 60–70K tiles each (~37 million tiles). Not the 3,287-entry continental blowup of 07-23, but the same root path.

⛔ Bbox refresh jobs RESET rather than complete — observed twice: a job at 5% went back to 4%, then a second reset the same way. Distinct from the known never-completes stall.

⭐ Design decision (Fred) — refresh gets two methods

CORRIDOR IS THE DEFAULT. Route refresh through the track selection process — reuses proven code, kills the oversized-cell problem for free (the corridor worker re-derives tiles at run time), and matches what refresh is actually for.
AREA REFRESH STAYS AS AN OPTION for users who downloaded areas. Same shape as the download side (downloadType selects the worker).
The area path must move from gridCells to segmentCells. Corridor-by-default only reduces how often the defect is hit.

⚠ A select-all-tracks refresh needs an estimate-and-confirm gate — the import path does one submitDownload per track with no estimate, which is how 10 tracks became 215 jobs.

⚠ A failed queue job records no reason

A corridor job failed and the entry said only "CORR SAT failed" — no exception, no HTTP status. The cause was unrecoverable because TRACK-DBG: TICK (twice every 5 s) had already rolled it out of the logcat ring buffer.

Fix: put the failure cause in the queue entry AND the log. ⚠ TRACK-DBG actively destroys evidence — add it to the pre-release removal list alongside WAYPOINT-TRACE.

To catch it next time, start the capture BEFORE queueing: adb logcat -c then adb logcat | grep -viE "TRACK-DBG|DetailGate|NetworkStateTracker|WM-|chromium|ConvoyIntercept" > /d/corr_run.txt
