4a. CoT scope — what T5.4 converts (from the code, 10-15 08:03–08:18)

9. Lessons

  • Don't guess route names — copy what works (10-15): four Hide Mesh patches named destinations that were not on the back stack; the log line saying which way it went found it each time. The fix was the existing Settings mechanism.
  • Read the counts before naming a cause (10-15 09:59): the slow-map theory (GPS flooding the screen) was wrong — the TICKSHADOW counts showed 0–2 updates per 5 s; wpa_supplicant showed the Wi-Fi re-joining.
  • A new doc must carry the living master's decisions (10-14 22:41): plan v1 dropped the 10-06 "one cutover" decision and pushed CoT to later. Check the living master before writing a plan.
  • Compare a good startup log with a bad one FIRST (Fred 20:43): we had a recording of every install and still chased radios and configs. Tonight's 20:3x install is the recorded known-good startup.
  • A collector started in init runs at once on the main thread — everything it touches must be declared above init (the 12:14 crash).
  • A crash loop during Meshtastic's connect leaves half-open Bluetooth links — a plausible cause of the afternoon's Bluetooth trouble.
  • Never reason past evidence: every theory today that was not checked against the log was wrong at least in part (second app = Android's own service; "recovery ran before the first connect" — it did not).
  • Our own red message caused damage: it told the rider to Forget while the radio had just started talking.
  • Read the right tablet: with two plugged in every adb command uses -s <serial>.
