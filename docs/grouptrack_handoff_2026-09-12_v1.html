⛔⛔ The landmine — and only the cross-reference found it

ConvoyConfig.migrateTiles() was live, called from ConvoyScreen:960, and moved tiles FROM app-private storage OUT to shared storage — the pre-MBTiles migration, exactly backwards from where storage is going.

⚠ Once tileRoot() resolves internal its source and destination are the SAME directory: it would walk the live tile store renaming each source onto itself, then delete the parent if the listing came back empty. ⭐ A dest.exists() guard made every source skip — harmless BY ACCIDENT.

⛔ Its guard was a SharedPreferences flag while the data it guarded lived in shared storage. A guard and its subject with different lifetimes — the exact shape of the 08-16 reinstall wipe. Deleted with its call site.

⭐⭐ NO DESTINATION-GREP WOULD HAVE CAUGHT IT. The dangerous line reads getExternalFilesDir, which LOOKS like the place we are moving toward. Fred: "that is why we created the tools. Too many scares."

⭐ The same sweep proved the blast radius was contained: of 42 files doing file work, most use context.filesDir — already app-private — or derive from an accessor.

⭐⭐ Housekeeping — the rules, and why rule 6 mattered

⛔ THE BUG: run()'s first line read the schema marker and returned, so ONE job's "nothing to do" skipped every other job. The manifest sweep never ran on a normal launch.

  1. ONE CONTAINER, called once after authority, before any map loads.
  2. SEQUENTIAL, NEVER CONCURRENT — what makes ordering meaningful.
  3. ⛔ TWO PHASES, init() IS THE BOUNDARY. It OPENS the files. Movers above, content-touchers below.
  4. ⛔ EVERY JOB GATES ITSELF, and no job's condition may stop the stream.
  5. INSERTION REQUIRES IMPACT ANALYSIS.
  6. ⛔ A JOB RETURNS FROM ITSELF, NEVER FROM THE CONTAINER.

⭐⭐ A JOB CANNOT GATE ITSELF UNTIL IT IS A FUNCTION. With the body inline, "return when there is nothing to do" and "return from the container" are THE SAME STATEMENT. ⚠ The first attempt moved the marker check below init() and it STILL returned from run() — same bug, one phase lower, and it looked fixed.

Fred, 09-12: "you could embed a job in a condition you did not see. All the code is inline and that is a lot to read to insert a new task."

The conversion, as built

One broad pick on Documents; the app finds both folders itself. ⛔ It reads EXACTLY TWO — the grant is broader and only discipline in the code enforces the limit.

The record IS the flag. Per-item source and destination bytes, the exception text, the granted URI, a timestamp per step.

Maps parked to Documents/maps via moveDocument, then copied largest-first, each source deleted only once its size matches.

⛔ Why parked rather than left in place: leaving GroupTrack to hold them "masks the location of where we are retrieving other components — we could run fine until we finish copying maps."

Space check against the LARGEST SINGLE FILE, plus a reserve. SAT.mbtiles is 16 GB in one file and no loop can split it. Droid 1 (86 GB free) copies; Droid 2 (16 GB) will refuse — that branch is still untested.

⛔ The renames stand where the deletes go. The field build swaps one operation. ⭐ And a rename makes a stale path fail LOUDLY.

⚠ What went wrong today — all of it mine

1. The buttons were unreachable. They went on ConvoyFieldRadioScreen — V3 Phase B, parked, nothing navigates to it. The conversion was never invoked: no logs, no record, files directory empty. ⭐ "Convoy radio menu" was matched to a FILENAME. A LABEL search found the real sheet in one step. The guess cost a 24-minute build.

2. LaunchedEffect(Unit) fires regardless of an early return. The storage prompt flashed past because the effect was declared ABOVE the return.

3. Compose reacts to State, not to facts. chooseMode() set a plain @Volatile field; the log reported SESSION MODE three times while the screen sat there.

4. onDismiss() disposes the launcher. The menu item closed the sheet before launching the picker. ⚠ The other five items use that pattern correctly — they navigate away and never return.

⭐⭐ 2, 3 and 4 share one cause: assuming a framework would notice something it was never watching.

5. Literal escape text in the source. Two patches wrote \u005Cu26a0 into Kotlin comments as six characters. ⚠ Every anchor into those files now needs the literal form. ⛔ A cleanup pass is owed on StartupHousekeeping and GroupTrackConversion.

6. Seven more guards refused correct patches, same shape as yesterday's five. ⭐ Brace-match the function, scope to what changed, strip comments first, and guard presence before comparing indices.
