1 · The markComplete refreshMode collision — ONE LINE, highest value

DO THIS BEFORE THE ETA WORK ConvoyDownloadQueue:549 branches on entry.refreshMode and silently removes the entry from the queue. But enqueueArea and enqueueCorridor both set refreshMode = replaceExisting.

So any download submitted with REPLACE ticked is deleted on completion instead of marked COMPLETE — no completion row, no completedAt stamp, no ETA sample. Fix: branch on downloadType == MAP_SOURCE_REFRESH.

Why first: it is one line, it plausibly explains BOTH the refresh-never-completes report AND a large share of the ETA being 50× long, and any ETA measurement taken before this fix is untrustworthy. Give it its own patch so its verification is not tangled with anything else.

2 · Settle SAT-frozen-at-15 — one download, no code

GATES PROMOTION PAST THE INTERNAL TRACK Run the same track's corridor with REPLACE TICKED. Replace bypasses the hasTile pre-fetch filter, so SAT must derive and fetch its full corridor.

  • SAT returns in the thousands → the filter was working, 15 was honest remaining work, nothing is broken.
  • SAT returns 15 again → SAT corridor derivation/fetch is broken, and the ≈90% headline measures what was QUEUED, not what LANDED. Testers would be getting corridor downloads with no satellite imagery.

Costs one download and no code. It is the only open defect that changes what a tester actually receives.
