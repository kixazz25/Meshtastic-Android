🔎 Platform rules found today (they govern all shared code)

  • Regex \s differs: Android (ICU) = Unicode White_Space (incl. the no-break space); the iPad (Kotlin/Native) and a desktop JVM = ASCII only. Shared code writes GtRx.WS (Android's set spelled out), never \s ([\s\S] = any character is fine). Used in GtRiderTrails now; 30 uses still to sweep in one pass + re-cert (GtGpxParse 10, GtImportConverter 19, GtRoute 1, GtGeom.parse 1) — Fred 15:02 plan A.
  • Kotlin's own number-to-text differs on the iPad: any text that is stored or hashed (WKT, bbox) is built with GtGeom / GtJava.jd. The 2.7e import builds trail and route WKT with "${lon} ${lat}" — 15e builds it with GtGeom.lineLonLat (identical on Android, correct on the iPad).
  • Regex.findAll on file text → GtRx.findAll (Kotlin's findAll copies the whole text per match on Android).
  • adb cannot read the app's databases or map stores on a release build when SQLite created them private (-rw-------, seen on Droid 2); files the app copied are group-readable. Anything that must read them from the Mac goes through the app (a request-file TEST-ONLY mode).

📐 The rule for V3 (Fred 18:15–18:16, agreed)

When the databases unify on AWS (V3), any value two devices compute differently becomes a conflict, a duplicate, or a row that looks changed. Anything stored, hashed or synced must be produced identically on every platform, proven by a golden test on the Droid's own answers; where an exact match is not possible, a canonical form is stored (UTC times with a fixed precision; distances to fixed decimals). The three to protect: geom_hash (made from the geometry's TEXT — one digit different = two copies of a trail on AWS), times (onX fractional seconds), stored computed numbers (distances, elevation gain, speeds).
