GroupTrack — Tooling & Troubleshooting Reference

Created 2026-08-05 · additive section for the Living Master · branch feature/convoy-event-ride
WHY THIS EXISTS

Four separate defects this week shared one shape: a method aborted before its real work, silently, and no structural tool could have found it. The existing xrefs answer where is this touched. Every one of these bugs lived on a different axis — on what thread, in what lifecycle phase, against which page. This section documents what each tool can and cannot answer, the execution-context contracts that have no tool at all, and step-by-step recipes aimed at specific results.

1 · The xref tools — what each one actually indexes

All three live in the repo root and are regenerated on demand (recommit rebuilds them). They are DEFINITION / SYMBOL INDEXES, NOT A CALL GRAPH.

ToolIndexesUse it to answer
field_crossref_raw.txt Field and property declarations with [R] / [W] markers and line numbers Who reads and who writes a field. The 08-02 source-persistence root cause came straight out of this: MapSourceManager had exactly two writes, both the API-keys file, so nothing persisted a slot. A field with many [R] and no [W] is a value nobody maintains.
where_used_raw.txt Symbol occurrences by file and line Blast radius of a rename or signature change. First stop before touching a shared symbol.
function_universe_raw.txt Function declarations with signatures and locations Does this function exist, where, and with what signature. Also the starting list for a dead-code sweep — but see §4 before deleting anything on its say-so.
grep Raw text CALL SITES. Source of truth, always. Use --include='*.kt' to skip .bak_* files.
THE STANDING RULE

xref for candidates, grep for call sites. The xrefs give signatures and locations; they do not tell you who calls what. Every time that rule has been skipped it has cost a session.

⛔ THE PATTERN BEHIND ALL FIVE

Scanning for one shape of evidence and reporting "clean" when the scan could not have seen what was there. A negative result from a grep is only as good as the pattern. Before trusting an empty result, prove the pattern can match a known-present case.

2 · Layer contracts — the axis with no tooling

These are execution-context rules. Violating one produces valid, compiling code that silently does nothing. Every row here was discovered by a production failure, not by review.

onPageFinished main Page is not ready until the postDelayed completes. Kotlin→JS calls before it fail with <fn> is not defined — visible only in a console log. 07-30, still live

⭐ AUTOMATABLE — the one check worth scripting

Row 1 is mechanical: scan for WebView/UI calls inside @JavascriptInterface method bodies (brace-depth walk over the two screen files) and report them. Seconds to run, and it would have caught ConvoyMapViewerScreen.kt:717 the day it was written.

It also answers the divergence question for free: run it against both screens and diff. Convoy clean, planner flagged is the output that would have ended 08-05 at 9am instead of 4pm.

3 · Divergence is a defect until proven intentional

Convoy is the reference implementation. Four times this week convoy had a fix the planner did not, and nobody knew until it broke:

  1. [Fix2] fresh re-read of MapStateStore — convoy :728. Planner still read a first-compose remember. (fixed 08-05, PLANNERSEED)
  2. Seeding lastViewport* before draw — convoy :730-733. Planner had no equivalent. (fixed 08-05)
  3. Posting evaluateJavascript to main — convoy does it via SpatialDisplayManager. Planner called direct. (fixed 08-05, VIEWPORTMAIN)
  4. Reseed gate — convoy dropped it 07-01; planner retains it. This one IS intentional (convoy is persistent and owns one map identity; the planner is entered and left, and the gate prevents cross-map bleed).
⚠ THE LIMIT

The maps are not symmetric by nature and should not be forced to be. Convoy has no entry event; the planner does. Making the lifecycles identical would reintroduce the contamination MapStateStore exists to prevent. The target is SHARED CODE, not MATCHED CODE — two hand-maintained copies drift again no matter how carefully aligned today. SpatialDisplayManager has been the reliable layer all week precisely because there is one copy. This is the same argument that makes the 2.7 service-layer work worth doing.

4 · Recipe — dead-code prune (2.7)

⛔ READ FIRST — THE TRAP UNIQUE TO THIS CODEBASE

Kotlin calls JavaScript functions BY NAME, from inside a string. ConvoyMapViewerScreen.kt:578 calls showProximityPopup that way. No JS tool sees that call. No Kotlin tool sees it either. A JS function with zero references in the HTML can be fully live; a Kotlin function whose only caller is a nav registration can be fully dead. Neither toolchain crosses the boundary — you are the only thing that does.

The sequence — do not skip a step

  1. Candidate list from function_universe_raw.txt.
  2. Grep the Kotlin for the bare name: grep -rn "name" --include='*.kt' app/src/
  3. Grep the ASSETS — both map HTMLs and any .js: grep -rn "name" app/src/main/assets/
  4. Grep for the name inside STRINGS — this is the cross-boundary step and the one that gets skipped: grep -rn '"[^"]*name[^"]*"' --include='*.kt' app/src/
  5. Check nav registration. A destination can be registered with no navigate() caller — e.g. ConvoyRouteCreateScreen.kt, a 27-line stub registered at ConvoyNavigation.kt:87 and reachable from nowhere.
  6. Confirm at runtime before deleting. Add one log line, build, exercise the app, confirm silence. Cheaper than a wrong deletion.
  7. Delete WITH its caller, in the same commit. Never leave a dead pair for later.

5 · Recipe — "it should draw and it doesn't"

The 08-05 sequence, generalised. Each step is a measurement, not a theory.

  1. Prove the channel before believing silence. Console tags: planner MapJS · convoy ConvoyJS · sources MapSourceMgr · workers CorridorWorker/DownloadQueue/TileDownloader/Corridor. Filter the FILE, never the stream — a bad pattern on a live stream is indistinguishable from a silent app. 
    adb -s <serial> logcat -d > /d/cap.txt && wc -l /d/cap.txt
    Use -d (dump and exit). Streaming with a pipe does not respond to Ctrl-C in Git-Bash and truncates silently.
  2. READ THE HEAD OF ANY STACK TRACE. The 08-05 root cause was at frame 99 of a trace present in every capture from 9am; the exception type was one line above it. Nobody read up.
  3. Partition with gestures, not code: cold start → direct entry (no other map first) → pan → fit. Which gesture fails localises the defect faster than any read.
  4. Compare against convoy at every step. A hypothesis that cannot answer "then why does convoy work?" is dead before it costs a build.
  5. Separate stale from absent. Wrong-region artifacts = a bad bbox. No artifacts, prior content persisting = the draw never ran. Conflating these cost most of 08-05.
  6. Watch for residue on the shared WebView. Convoy is persistent; its drawn layers survive. Artifacts on the planner may be convoy's pixels, not the planner's output. Any test that visits convoy first is contaminated.
