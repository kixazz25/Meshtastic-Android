⭐ THE TEST OF THE 95% NUMBER (SVC95-2026-11-21, Fred 08:43)

Fred’s standing claim (SVCSTALE) is that “95% of needed services already exist[].” It was asserted, so it was worth measuring. Method: every capability actually needed by today’s work was queried against the generated services index (svcref_2026-11-21_v2.py --find <capability>), by capability only — never by a symbol name already known, since searching by the other platform’s name is the mistake that produced the nine phantom holes.

Result: 14 of 16 capability probes landed on an existing cross-platform service. 2 missed.

The two misses were not random, and that is the finding. They are reachability / internet / online and background location permission — precisely the two new-service candidates the hand walk of B–M had already named, reproduced independently by a tool that had not seen that walk. Both are platform-capability seams (network state, OS permission), not computation. Every computational need — haversine distance, number formatting, time-zone arithmetic, JSON, locking, file access, SQLite, build info, the lead-track producer, map key, filter — was already there.

Verdict, stated honestly: 87.5% on this sample, and n=16 is far too small to tell 87% from 95% — two probes either way moves it six points. What the test does establish is the shape of the remaining 5%: the service layer is essentially complete for logic and computation, and the holes are concentrated where the shared layer has to reach a platform capability. That is a better planning rule than the percentage: assume the computation exists; expect to build at a platform seam.

⚠ AND IT IS AN ESTIMATE, WHICH DOES NOT REPLACE THE HAND CHECK. Fred 11-21 08:47: “calc is an estimate anyway. we will examine by hand before [creation].” So this percentage is a planning number and nothing more. The gate before any service is created stays what it was (C28-26361 SVCFIRST): query the index, then examine by hand — iosMain and androidMain greps, the service-layer design catalog, and what ANDROID calls at the same hop. A query is how you find a service; a hand walk is how you establish one is absent. The tool narrows the search; it never closes the question.

⚠ The negative witness for this test. If the index were merely matching on common words, the probes would have hit on everything, misses included — and reachability would have come back with a false positive instead of three weak hits in unrelated packages. It did not.
