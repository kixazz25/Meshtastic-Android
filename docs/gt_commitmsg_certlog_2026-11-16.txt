WHY THE SOURCE DIFF WAS NOT ENOUGH. gt_logkermit's old/new report proves the TRANSFORMATION is
right -- the text written is the text intended, for all 994 sites. It says nothing about what the
app EMITS. If a tag, a severity or one character changes, the log stops being 2.7e's log and every
log-reading instrument we own (gt_execscope, the cert harness, the deploy recordings) silently
changes meaning. Those are different claims and only the second one matters here.

WHY THE WHOLE CORPUS AND NOT A SAMPLE (Fred 08:06: "one special character somewhere could wreak
havoc"). The census over the 994 real messages: 2548 quotes, 1455 dollars, 724 brace pairs, 95
apostrophes, 88 newlines, 24 backslashes, 13 percents -- and 37 NON-ASCII characters (34 em dashes
U+2014, 3 arrows U+2192). A 12-case sample would have missed every one of those, and they are
exactly where Kermit's Android writer and its iOS writer can diverge.

THE CORPUS IS DATA, NOT GENERATED CODE. Real call sites interpolate locals that cannot exist in a
harness, so each message's literal skeleton is carried verbatim in a TSV and read back at runtime.
"${entryId}" is therefore inert text, which makes this the strictest form of the test: it compares
the exact character sequence with no interpolation in the way. 994 rows of data are also reviewable
and diffable, where 994 lines of generated Kotlin would be one more thing to get wrong.

FOUR FILES, MODELLED ON Cert17mbtiles / GtCert17mbtiles / GtCertMBTiles17MacTest -- not invented:
  CertLog.kt (shared)        one Side at a time, emitting key -> value, as Cert17mbtiles.run does.
                             newSide() runs Kermit through a capturing LogWriter whose signature is
                             copied from NordicBleInterfaceTest:61, which compiles today. Platform-
                             free, so the Droid and the iPad run identical code and a difference
                             between them is a PLATFORM difference.
  GtCertLog.kt (app)         OLD = what android.util.Log is handed; runs both sides and writes
                             CERTLOG <tab> key <tab> SAME|EXPECTED|DIFF <tab> value, footer
                             "# CERTLOG done: N SAME, N DIFF, N EXPECTED".
  GtCertLogMacTest.kt        loads ONLY the Droid's SAME lines, fails if the Droid's own OLD vs NEW
                             already differs, runs the same shared newSide() over the same corpus,
                             and asserts 0 differences. Non-ASCII differences are reported as
                             UTF8-FACT rather than buried, the way the mbtiles test calls out
                             ENGINE-FACT.
  gt_cert_v48.sh             mode certlog: pushes the corpus (verifying line counts), runs the
                             Droid, pulls the report to gt_certlog_droid.txt, slices the fenced
                             logcat blocks, runs the iPad test, prints
                             "Droid OLD = NEW: ... iPad = Droid: ...".

TWO PASSES, because they certify different things:
  PASS A -- the report: what android.util.Log is HANDED against what Kermit's writer RECEIVES.
    Catches a changed tag, a remapped severity, any altered character between call and writer.
  PASS B -- the fenced logcat blocks (Fred 08:13: "a process that writes the logical messaging to a
    logcat file with a specific identifier so we can access the log file"). Every case emitted FOR
    REAL through android.util.Log, then through gtLogger, between
        CERTLOGFENCE: BEGIN OLD run=<id> / BEGIN NEW run=<id> / END run=<id>
    gt_cert already records the whole run (v47 lines 309-310), so both blocks land in that recording
    and are compared POSITIONALLY. The identifier is in the FENCES, never in the messages --
    prefixing a message would alter the very text under test, and identical OLD and NEW lines are
    indistinguishable by content, which is the point.
  Pass A proves the inputs match; pass B proves what logcat actually received. A disagreement
  between them localises the fault to platformLogWriter.

THE TEMPLATE FOR THE REST OF TODAY. Generic and reusable unchanged: corpus-as-data, OldSide /
