The group story — captured today, for the manual

  • A rider needs only a radio. No phone, no app. Six riders needs one person running GroupTrack and five carrying radios.
  • Clubs can buy a pool at about $45 each, hand them out and collect them. The rider handed one needs no knowledge and no setup.
  • It works out of the box — every install ships a default config that supports any group. The unique config answers a problem that does not exist yet: two rides within a couple of miles seeing each other.
  • T1000-e recommended — credit-card size, about two days of battery, wears on a lanyard, and it is the one the app configures, roughly thirty seconds a radio. Any other radio and you apply the settings yourself.
  • Club vs ad-hoc — a club configures once and rides its own network; an organiser sends route and radio config per ride.

The riding button group, described for the first time: GROUP frames the whole group front to back showing gaps · MY CART centres you at constant zoom with distance to the riders ahead and behind · SELECT CART chooses a cart or removes one (breakdowns, early departures) · HIDE frees the map · Settings covers map sources through group-riding radio behaviour.

Worth remembering

  • Look for the existing component before writing a new one.
  • Put a control where the working controls already are. The mesh fold control was invisible twice, both times drawn in a layer it did not own.
  • TrailFilterState is a plain singleton, not Compose state — every composable reading it needs tick.
  • Anchors from cat -A, never sed.
  • Three hand-edited lines per release that nothing prompts for: the label in ConvoySettingsScreen.kt, __htmlVersion in both map HTML files, and the schema marker when the trail schema changes.
