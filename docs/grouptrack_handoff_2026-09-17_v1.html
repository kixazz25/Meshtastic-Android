⭐⭐ The crash every non-Utah rider was hitting is fixed and shipped, and the 78 MB read underneath it is gone — replaced by a streaming parser VERIFIED BY EXACT COUNT.

⛔ The real cause: every non-Utah import was doing Utah's work

The ownership data is UTAH SITLA. The only test was whether the FILE EXISTS — not whether it is relevant. So importing New Hampshire:

  1. downloaded 78 MB of UTAH data over the network;
  2. parsed it into rings;
  3. built a cell grid indexing each ring into every cell it spans;
  4. walked the full trail cursor with both still held;
  5. and classified New Hampshire trails against Utah polygons.
OutOfMemoryError: Failed to allocate a 360 byte allocation
with 1670512 free bytes, growth limit 268435456
  at CursorWindow.nativeGetString
  at HomeStateImportController$executeRun$2$changed$1

⛔ A 360 BYTE allocation against a FULL 256 MB heap — death by accumulation, and the failing frame is a DATABASE CURSOR, not readText. This morning's heap guard never even runs on that path.

⭐⭐⭐ SO IT WAS NEVER A LOW-MEMORY-DEVICE PROBLEM. It was EVERY RIDER OUTSIDE UTAH, on any device. Droid 1 has 256 MB and still died. ⛔ And it dies on the LAST stage, so a rider who tried and gave up appears nowhere but Crashlytics.

⚠ UTAH HAS NEVER CRASHED — same code, MORE trails. Everything aimed at "protecting Utah" was solving a problem that did not exist.

🔵 SRCFRESH-2026-09-17 — skip sources that have not changed

Test the DB for an existing source; if the remote has not changed since, skip it entirely.

⭐⭐ The evidence is in today's manifest: the Utah rerun fetched 49,125 UGRC records to insert 52. A rerun pays the full cost for almost none of the benefit — 27–31 minutes.

⭐ And it is exactly what area downloads need — an area download over a state already held re-imports everything to insert nothing.

⚠ Per source, not universal. ArcGIS reports editingInfo.lastEditDate; Geofabrik exposes a file date. Check what each offers, store it on success, compare next time. ⚠ Must be overridable or it becomes a trap when data is suspect.
