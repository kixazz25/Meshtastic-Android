Fred 10-18: the app is overwhelmingly complex, and navigation must be simplified. Take the screens out of processes and move their value forward to the processes that call them, so we are not nesting six layers deep. Each flow executes one task. The rule each flow must meet:

  • ONE launch screen collects everything the task needs, with defaults pre-filled from the ride or settings.
  • It hands those values to a process function as parameters.
  • The process runs to the end with no further screen prompts.
  • A process never opens another screen to get a value; that value is a parameter or a default.
  • The only allowed stop is a confirmation before something destructive or irreversible.
  • No screen-to-screen chains.
