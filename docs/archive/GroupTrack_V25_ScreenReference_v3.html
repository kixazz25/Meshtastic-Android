TRAIL SOURCE RULES:

- Vetted/approved sources only. This IS an asset.
- Each source: name, URL, format, trail type, boundary
- Boundary = qualified lat/long coverage area
- Catalog built here. Actual import via Work with Artifacts.
- Build functions first, identify resources second
- BLM, USFS, state-specific = known candidates

IMPORT FLOW (uses this catalog):
1. User draws area on map
2. Area compared to catalog boundaries
3. Overlapping sources suggested
4. User selects sources
5. Download from URL in defined format
6. Filter to user's area boundary only
7. Dedupe + import to SQL db as trails
8. Triggers tile refresh (LOW priority)

QUEUE RULES:
- Three separate queues, never mixed
- Button upper right of map (both maps)
- Summary + twisty drill-down + priority filter
- Same display template for all queues
- Closes to nothing when done

TILE TRIGGER RULES:
Trails: refresh downloaded tiles only (LOW)
Routes + Tracks: refresh AND create tiles (HIGH)
Source refresh: replace existing tiles (MED)
Remove area: delete stored tiles (LOWEST)
All trigger-based. Never standalone tile download.
Exception: manual area draw for initial tiles.
