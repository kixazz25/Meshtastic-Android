5. Bbox state selection is over-inclusive — decided, not built

Measured: findByBbox tests the drawn box against each state's RECTANGLE. California's reaches east to -114.13; the box's west edge was -114.573. So California was selected, downloaded (600 MB+), extracted, imported ZERO trails, and swept. A rectangle tested against a rectangle can only ever be a rectangle.

⭐⭐ DECISION (Fred): the deselect checkbox is the fix, on the bbox confirmation screen the 08-18 mockup already specifies. No network dependency, no tuning parameter, no failure modes — and honest: the rider knows the ground, the app does not.

The panel must EXPLAIN the mechanism, not just offer the control. Draft wording:

Some states may not have trails in your area.
States are matched using a rectangle around each state, and those rectangles overlap. A state can be listed here without reaching into the area you drew. If you know a state isn't part of your ride, uncheck it — you'll skip its download.

  • ⚠ Keep "bounding box" out of rider-facing text — audience is riders 65–75.
  • Default ALL CHECKED. Over-inclusion costs time; under-inclusion costs coverage the rider does not discover until they are out there.
  • Show the download size per state if available — that is what makes the choice real.

💡 Considered and NOT chosen: perimeter geocoding. Sample the box edge every ~10 mi, reverse-geocode each point, deselect any bbox-selected state whose name never appears. ⭐ Fred's insight: a state cannot be inside the box without crossing its edge, so perimeter sampling is complete for a rectangle and interior points add nothing. Measured on the real box: 28 sample points, 11 west of California's bbox edge. Written and parked as resolveStatesByPerimeter_2026-08-21.kt. More correct in principle; costs a network round trip, a tuning parameter and three failure modes to buy what a checkbox does for free. ⚠ If ever revived: bbox proposes, perimeter DESELECTS — never let the geocoder add, and deselect nothing when lookups fail.
