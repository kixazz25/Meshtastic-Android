⭐⭐ THE TURNING POINT, and it was not technical

Fred, 08-26: "trying to rationalise the old engine with components that were not built for the problem we were solving was the turning point. Natural resistance to replacing the familiar with the unknown. But the familiar was a round peg in a square hole."

The greedy was built for "find me a ride somewhere near here." Once the question became "reach these places, from where I am standing, and show me options", it was the wrong tool — and no amount of tuning fixes a wrong tool. Yesterday afternoon went on adjusting weights and thresholds on a mechanism that could not answer the question.

⚠ The resistance was mine. Fred proposed replacing it early; I kept proposing patches. Every wrong theory yesterday was an attempt to make the familiar thing correct.

⭐ RULE EARNED — it will come up again in the convoy rewrite: when the question changes, check whether the mechanism was built for it BEFORE tuning.

⭐⭐ PROTOTYPE-FIRST PAID FOR ITSELF SEVERAL TIMES OVER

35 engine revisions in a day, at ten seconds a run instead of thirty minutes a build. Fred set the rule this morning after the previous day; it is now standing.

⭐ And it was not only speed — it was the freedom to be WRONG.

  • The subset proxy looked obviously correct and was not — it counted six independent feature sets, stopped, and the real overlap test then dropped one to five.
  • The detour screen measured from the wrong points twice.
  • Removing the cap entirely ran forever.

Each was a ten-second lesson instead of a wasted evening. And the things they found — ride 6 at 79.7 mi that stopping early would have thrown away, the 80% overlap between rides 4 and 6 — would otherwise have shipped silently.

⚠ Carry it into the next phases. The approval panel reads a JSON file, so it is testable against a hand-written batch with no engine run at all. Same principle, applied to UI.

The algorithm, settled

corridor (ceiling/3) → graph → candidate starts within 600 yds, EDGE-SPLIT
  → collapse to one origin per component (alternatives kept)
  → features via spatial grid, on ANY origin's component
  → rider pins as high-value features, split onto their trail
  → distance matrix → out-and-back filter → pairwise table + TESTED ceiling
  → working array: features earn their way in
  → ENRICH the top 20 (rides x features, not combinations)
  → dedupe: same origin+features · any origin · 75% shared trails
  → six

Fully annotated with every measurement in GroupTrack_algorithm_annotated_2026-08-26.html.
