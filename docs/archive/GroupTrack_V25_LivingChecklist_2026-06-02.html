L. DB Revision — Correctness Invariants (why the structure)

Insert-boundary guard = PERMANENT gatekeeper, not one-time cleanup. Data keeps arriving (device→AWS, AWS→device, device→device); each delivery is evaluated FRESH against the receiving DB: same name+geom → DROP; new name+same geom → ALIAS; geom absent → INSERT. Two-layer: UNIQUE structurally guarantees DROP; app-logic makes the new-name→ALIAS call.

First-occurrence / local-primary invariant (~100 contributors): same physical track may be primary under a different name in each DB (whoever arrived first there); the set {primary + all aliases} must be IDENTICAL across DBs. Completeness of the name-set is the correctness test, not which name is primary.

Two things to PROVE in testing: (1) geom_hash normalization load-bearing — same trail with rounding-different WKT must hash the same (normalize coords before hashing; test on real agency dupes). (2) Local↔AWS structural identity — same UNIQUE key both sides or the alias model breaks at sync. This is why the AWS mirror is correctness-critical, not cosmetic.
