2. Decisions needed from Fred before code

D1 — who judges "talking"? Today GroupTrack's tick decides (own TAK report within 45 s, else node-list traffic within LINK_SILENCE_MS). Option (a): the comm side owns link health — it sees the radio's traffic — and reports it as an event (additive: CommEvent.LinkHealth(talking, quietSinceMs)); GroupTrack only shows it and decides on recovery. Option (b): keep the judgement in GroupTrack using lastReportFromMs (already API) and a new additive "last traffic" timestamp from the comm side. Proposed: (a) — "is the link alive" is a transport fact; on IP or Apple it is measured differently.
D2 — who decides WHEN to recover? Recorded rule 10-08: recovery is a request, the action is performed in the comm module, reconnection is an event. Proposed: GroupTrack keeps the timing policy (3 tries 45 s apart, then 2 min; banner only while riding with a group — it knows the ride) and calls reconnect(); the comm side does the disconnect → wait → reconnect it does today and reports LinkChanged.
D3 — the radio list. Today GroupTrack's panel embeds Meshtastic's own ScannerView (a Meshtastic screen piece inside a GroupTrack panel — against "GroupTrack owns the panels, comm is headless"). Headless replacement: the comm side scans and publishes radios: Flow<List<RadioEntry>> (+ startScan()/stopScan(), additive); GroupTrack draws the rows. Risk: Meshtastic's scanner also handles Bluetooth permission prompts and the scan lifecycle. Proposed: split — P2a without it (everything else), P2b = the headless list, planned on its own.
D4 — the name table. RadioNameStore is GroupTrack code living in Meshtastic's core module. Proposed: it belongs to the comm side (names are what the radios call themselves); GroupTrack reads names only from RadioEntry.name / DeviceInfo.name / member callsigns.
D5 — pair vs connect. Meshtastic's onSelected pairs an unpaired radio and connects a paired one. Proposed: one request, connect(id), does both (Capabilities.pair = true on Android); the panel still says PAIR or CONNECT from RadioEntry.paired.
