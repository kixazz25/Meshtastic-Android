The side alleys — three defects in the display path

1. "Not Named" is a name

The map query ordered named trails first via name IS NULL OR name = ''. But ~69% of rows carry the literal string "Not Named" — neither null nor empty — so tens of thousands of placeholders sorted as NAMED. A 200-foot connector outranked a ten-mile track. Fixed: order by extent alone.

2. A second query nobody was looking at

The row list is queryArtifactList, not queryTrailsByViewport. Different SQL, and ORDER BY name LIMIT 200. ⭐ Fred said "rows start at 200" for hours and I kept answering I could not find a 200. It was at SpatialDbManager:1987. Alphabetical, so numbered roads fill the list and anything starting with S never gets near it. Not fixed — it cannot explain a list of 34, but it will bite at 200+ trails in view.

3. Per-trail selection was a trap

SpatialDisplayManager filters to checkedIds when the state is SELECTED, so a trail imported after that list was saved silently never drew. Fixed: SELECT greyed for Trails; a saved SELECTED reads as ALL so a stuck device recovers.

4. Unresolved: the list and the draw disagree

They come from different queries. If the list is meant to document what was drawn, they have drifted — a defect in itself. If it is an independent view, its disagreement proves less than it appears to. Worth settling which.
