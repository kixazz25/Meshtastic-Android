TASK DESCRIPTION
----------------
Replace the fixed-12-mile area-download grid with a load-balancing
segmentation that splits any download bbox into equal-area cells sized so
no single cell exceeds ~50,000 SAT tiles, so parallel download slots do
comparable work and finish together instead of one giant job stranding a
slot for the long tail. Goal: make download balance STRUCTURAL rather than
the accidental luck of the old grid.

- OVERLAP (final, correct): pad = if(n>1) overlapTiles × (360 / 2^zMax)
  else 0.0 — i.e. 3 tile-widths ~0.004 deg at z18, applied outward on every
  edge, SEAM-ONLY (a 1-segment area gets ZERO pad). hasTile() dedupes
  overlap fetches -> zero redundant storage.
  HARD-LEARNED: overlap must be TILE-WIDTHS, NOT degrees. Earlier specs of
  1/8 / 1/4 / 1/2 degree were ALL catastrophically wrong — 1/8 deg at z18
  ~= 91 tiles/edge, which ballooned a 24,716-tile area to 155,674 (6x) in
  the dry-run JSON. One tile at z18 = 360 / 2^18 = 0.00137 deg. Never pad in
  fixed degrees.
