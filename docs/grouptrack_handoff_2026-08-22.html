2. 🔴 THE GPX IMPORT STORY — read this first

Testers could not import routes. ConvoyTrackOps.kt carried a TEMP BYPASS from 2026-06-02:

val waypoints = emptyList<GpxWaypoint>()  // was: parseGpxWaypoints(text)
val routes    = emptyList<GpxRoute>()     // was: parseGpxRoutes(text)

⭐ Everything downstream was already complete — insert loops, WKT build, bbox, type mapping. Only the two parser calls were stubbed. A deliberate hold that outlived its reason by nearly three months. AllDocs had recorded it: "import currently processes tracks only."

✅ FIXED. Broken Ridge 2 imported to Droid 1 — 31,845 chars of geometry, correct bbox. Also fixed: the <rte> regex matched only a bare tag, so <rte xmlns=...> imported silently as zero routes.

⛔ STILL BROKEN — the auto-import path, which is the one testers use

Manual from Downloads → Map Features: works. Tapping a GPX in email: fails for routes. The intent filter routes it to the old track-only function.

Why it is not a quick fix: the filters live on com.geeksville.mesh.MainActivity — Meshtastic's own activity — and declare <data android:scheme="content" />. The intent hands over a content:// URI while importGpxAllArtifacts takes a File. The stream must be copied to a temp file first — the same problem the OSM import already solved ("SQLite needs a real path").

⭐⭐ THIS BELONGS TO 2.7. GroupTrack behaviour inside Meshtastic's activity is exactly the entanglement the mesh separation removes.

TELL TESTERS: save the attachment to Downloads, then import from Map Features → IMPORT TRACKS, WAYPOINTS & ROUTES.

⭐ Panguitch produced the best rides because its ground is NAMED — Trail Creek, Upper Bear Valley Road, Showalter Mountain. The Arizona Strip is 77% unnamed track and its routes could not be described. Naming is what makes a suggestion communicable — the argument for the rider-naming channel in 3.0.

⭐ Broken Ridge: ONE unconfirmed junction in 79 miles against 176 on the Strip, same tolerance and code. The caution count is a property of the DATA, not the setting.

Four wrong turns, all recorded in the living master: distance must not be in the score (it is a budget, not a cost) · penalise edges, do not filter for distinctness · rank, do not pre-constrain · each restart needs its own target distance. Plus: a positive-score floor is required — two good routes beat four padded ones.

Coverage curve, measured: ~12 miles per feature, near-linear, no knee. All 39 features reachable at 448.7 mi. So a 60-mile ride reaching 4 features is what the corridor costs, not a bug.

🔴 Planner prerequisites, found by using it

  1. A WIP must open in ARTIFACT mode, not draw mode. One stray tap took Toroweap 1 from 78.8 to 109.0 miles with a 21.9-mile straight line. Two undos restored it — the geometry was never damaged.
  2. A lock field in the draft JSON — soft, rider unlocks deliberately.
  3. Fit-to-route on open, as track fit already does.
  4. ⚠ Sidecars currently sit in route_drafts/ beside the drafts.

⭐ NO POI WAYPOINTS NEEDED — Fred: "they are already on the map." reference_points came in with the OSM import and already renders.

4. 2.7 REDEFINED — mesh / GroupTrack separation

Scope, deliberately narrow: separate GroupTrack from mesh messaging · mesh becomes a plugin · a switch for mesh or IP-based GPS relay · IP is a STUB.

⭐ The stub is what proves the boundary is real — an interface with one implementation is a wrapper.

⛔ Explicitly NOT 2.7: relay rules, 3-second broadcast, hop limits, dedup, enrolment scoping, group addressing over IP. Fred pulled back when it started becoming a network protocol, and that was right.

⭐⭐ The hard part dissolves in 3.0: a ride already defines the radio broadcast group and its keys. Fred: "the same registration of a user with both radio and ip config groups available." One registration, both channels. So IP lands in 3.0 with the server and the paygate.

Licensing: the plugin boundary is a stronger argument than the April "convoy/ files are original work" claim, because it is about what depends on what. ⛔ Still a question for a lawyer — neither claim has been checked. Attribution (splash or per map source) is the easy half and has been open on the Play checklist since April.

6. ⚠ Method — mine

Three compile failures on a two-line change, all the same mistake. The bypass comment said parseGpxWaypoints(text); I restored it verbatim → unresolved. Substituted fullText from a grep → unresolved, because it was declared inside a run { } block.

⭐⭐⭐ Both failures were reaching for a variable NAME without checking its SCOPE. And a three-month-old comment is a record, not a specification.

⭐⭐ THE XREFS WOULD HAVE ANSWERED IT IN ONE LOOK. where_used_raw.txt showed fullText used only at 531–533, all inside the block. They were open the whole time. Fred: "we need to use the xrefs more to research." Standing correction: xref first, grep second, guess never.

⭐ And the obvious fix was wrong — a second readText would have compiled but doubles memory on files that already OOM'd. Hoisting the single read was correct.
