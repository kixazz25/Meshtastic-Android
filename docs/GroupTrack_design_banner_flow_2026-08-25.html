Banner flow — the checklist replacement

Design, 2026-08-25 · supersedes ConvoyGuidedPinPanel's step checklist · interactive companion: GroupTrack_mockup_banner_flow_v2_2026-08-25.html

⛔ BUILD THE ORIGIN FIX FIRST. Rider-placed points do not become graph nodes — the ride starts ~600 ft from the tapped waypoint and pins snap up to 6,001 ft. This UI is a revision to a process that must first be correct. Fred, 08-25: "these are ui revisions to a then proven process."

1. Why the checklist goes

  • It covers the map. A full-width panel of steps sits on the ground the rider is trying to tap.
  • It shows every step at once — overwhelming, and the live one competes with five others for attention.
  • Its exit is load-bearing by accident. PROCEED sets showAiDesign = false, and that is the only reason the route toolbar — which carries MAP TAPS ON/OFF — comes back. Close the panel differently and the rider loses the taps toggle entirely.
  • It made explore mode unreachable. DONE is absent while pinFeas == null, and zero pins returns null. Patch S1 added a question as a bypass; the banner removes the need for it.

3. What the shape buys

PropertyWhy
One instruction at a timeFinished steps disappear rather than stacking. Nothing to collapse, nothing to scroll.
The state lineWhat the checklist was really carrying. A rider who panned away still knows what they have built.
One CONTINUE for two meanings"I have none" and "I am finished" are the same button. No yes/no question, so S1's ASK step disappears.
The loop question answers itselfNo finish pin = loop. Nobody promises a ride shape before seeing the ground.
Green means viableGrey says the button exists but the ride is not ready. Better than absent, which said nothing. Same language as the radio config screens.

4. Three marker kinds

MarkerLookMeaning
TrailheadBlue square, THAlways visible. The rider must see where the ride begins even after panning.
PlacesRed circle, numberedDrop order, not tour order — Held-Karp reorders on every drop and markers must not renumber under the rider's finger.
FinishAmber square, FINOnly exists if placed.

⚠ MARKERS MUST SHOW THREE STATES, not one. Today every pin draws solid red including ones the engine discarded. PinFeasibility already carries snapFeet and unreachable.

  • On-trail — solid, drawn where tapped
  • Snapped — drawn at the snapped position, so the rider sees where the route will actually pass
  • Unreachable — hollow or grey, visibly not in the ride

Six of ten pins were dead on one run and the app said nothing. Same class as the invisible drop.

5. ⛔ The dependency that must not be missed

MAP TAPS ON/OFF lives in the route toolbar, which renders on routeMode && !showAiDesign. While the AI panel is open the toolbar is gone — so a rider mid-flow cannot toggle taps to read a trail name and get back.

The banner must carry MAP TAPS ON/OFF. That is not a nice-to-have; it is the reason the banner can stay on screen at all.

6. Mileage: the rider's job and the app's job

⭐ The rider is concerned with places, not distance. Fred, 08-25: "they should be concerned with mandatory points of interest, not using all the mileage."

Only the ceiling blocks. Under the floor is not a failure — it is headroom, and the engine fills it with the best features it can find. Leaving mileage spare is how the app earns its keep: ten pins consuming all 80 miles leave nothing to discover.

So the panel says: Drop pins on the places this ride must reach. Leave some mileage spare and we'll find more worth seeing along the way. And nothing else, until the ceiling is exceeded.

⚠ Consequence: the HUD's under-floor commentary should go. The Distance number earns its place — watching it move confirms a pin registered — but the line beneath it only matters when exceeded.

7. What this replaces in code

RETIRED   PIN_STEP_RETURN      the loop question — answered by placement
RETIRED   PIN_STEP_ASK (S1)    the bypass — CONTINUE covers it
RETIRED   the step checklist   GuidedStepRow, the six GuidedStep declarations
KEPT      PIN_STEP_NONE / TRAILHEAD / INCLUDE / ENDPOINT / SUMMARY / SEARCH
KEPT      pinPoints, pinFeas, assess(), the Distance HUD
NEW       banner: eyebrow + instruction + state line + actions
NEW       MAP TAPS ON/OFF on the banner

⚠ ConvoyGuidedPinPanel already takes expanded/onToggle and already scrolls (verticalScroll, heightIn(max = 300.dp)). Collapse behaviour is wiring, not new machinery.
