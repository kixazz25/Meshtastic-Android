The agreed UI spec for route creation. Build the actual Route+ toolbar against this. Approved look & feel: RouteBuilder_Toolbar_FINAL_v3.
Locked 2026-06-04  ·  supersedes the look-and-feel mockups  ·  the build target for the snap-2 slice
The test this pact enforces: when the panel is built, every use case with a defined action must appear on the panel (or be explicitly assigned to Work-with-Artifacts → Routes) with its proper action associated. No orphan actions; no actions without a home.

1. Panel split rule

The Route+ toolbar is for CREATE / BUILD only. Every other route action — copy a completed route, edit / rename / delete a completed route, view detail — lives in the Work-with-Artifacts panel under Routes (SEL/EDIT). Toolbar = build; artifacts panel = manage.

5. The only write points (persistence model)

Everything is in-memory while building. The ONLY writes: Save in-progress (create draft JSON), Save with changes (overwrite draft JSON), Save as completed (insertRoute DB row + delete draft JSON if one existed — graduation). NEVER written on: Roll back, Discard, remove-unsaved. A route is EITHER a draft-file OR a DB-row, never both. Drafts = private JSON in app-internal storage; completed = spatial DB row.

6. First-pass working loop (the snap-2 slice we build next)

+ROUTE → New (Add ON) → place snapped points → toggle Add OFF / collapse / drag aside to see the map → Undo as needed → Save as completed → buildWktAndBbox → insertRoute → route saved as DB row, drawn gold dashed → exit. Discard (new route) clears the screen, no write. Everything marked "soon" is a visible placeholder linked to its checklist item; the draft-JSON legs (Amend In-Progress, in-progress Save, roll-back) activate with the draft-I/O pass.
