ADDENDUM 2026-06-03 (later in session) — route entry & detail access refinements

K. Route entry model (REVISED — supersedes the toolbar source-picker)
- The Route+ toolbar's only live entry is "New Route" (blank chain, start from scratch).
- Copy-and-modify and Continue-in-progress do NOT live in the toolbar. They launch
  from the ARTIFACT ROUTE LIST instead (the SEL/EDIT list in the artifacts panel),
  because you must FIND and SELECT the source route first, and the artifact list is
  already the route-selection UI. Reuse it, don't build a parallel picker.
    - Select a route in the list -> "create based on this route" (copy & modify -> new chain)
    - Select an in-progress draft -> "continue" (resume)
- The route list needs SEARCH/FIND once there are many routes (not a raw dump).
- Rationale: path of least surprise; users already go to the artifacts panel to see/
  select routes. Same reuse-the-existing-pattern instinct as the rest of the build.

L. Artifact detail via the selector list (NOT map-tap) — expand selector detail
- PROBLEM: you cannot reliably tap a route LINE on the map to get its detail (thin
  lines, overlapping, poor touch targets). So detail MUST come from the SEL/EDIT list.
- Expand the selector detail to show full artifact detail info (name, length, type,
  status, etc.) in/from the list row — the reliable tap target.
- This closes the existing Living Checklist open item: "Trail/Route DETAIL via
  SELECT/Edit list (not map-tap); Trails read-only, Routes thin." Beef up the thin
  Routes/Trails detail here.
- Sequence: both K and L touch ArtifactListPanel and are downstream of routes EXISTING
  (need created routes before select-to-copy/detail matters). Build AFTER Method 1
  places points and saves.
