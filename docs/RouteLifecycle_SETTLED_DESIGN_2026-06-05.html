1 · Core rules (govern the whole lifecycle)

R1 — Either/or: a route is EITHER an in-progress draft (JSON file) OR a completed route (spatial-DB row). Never both. Graduation writes the DB row and deletes the draft.
R2 — Identity: in-progress identity = the typed NAME. DB identity = route id, assigned at graduation under dedup/alias rules. No route id exists while a route is a draft.
R3 — Save exits: every Save action (completed or in-progress) EXITS route mode. To continue editing an in-progress route, re-select it from the In-Progress list. No mid-session continue, no in-place state promotion.
R4 — State fixed at launch: New ⇒ NEW for the whole session. Select In-Progress ⇒ RESUMED for the whole session. Adaptive screens read this fixed state.
R5 — Writes are deliberate & minimal: the ONLY writes are create-draft, overwrite-draft, insertRoute(+delete-draft), delete-draft. Roll-back, discard-new, cancel NEVER write. Everything else in-memory.
R6 — Both maps: identical on convoy map (ConvoyScreen) and planning map (ConvoyMapViewerScreen), driving shared RouteManager. Two-file mirror. Endings: ConvoyScreen LF · ViewerScreen CRLF · Toolbar CRLF. cat -A before every patch.
R7 — Vertices not wkt: the draft stores the full vertex chain (lat,lon,lineId,lineType,segmentIndex,t,snapped). wkt/bbox are DERIVED at graduation by replaying buildWktAndBbox, so a resumed draft graduates through the IDENTICAL completed-save path.
