Meshtastic Radio Configuration Guide — Convoy Tracker

Purpose: Complete configuration reference for Meshtastic radios being repurposed for convoy tracking.
Important: These radios have been in service. Before configuring for convoy use, review ALL settings below — previous configurations may conflict with convoy tracker requirements.
Configuration Tool: Meshtastic Web Client at https://client.meshtastic.org via Bluetooth
Date: March 2, 2026

BEFORE YOU START: Reset vs. Reconfigure

Since these radios have prior configurations, you have two options:

Option A: Factory Reset (Recommended for clean start)

  1. Connect to the device via Web Client (Bluetooth).
  2. Go to Config → Device and look for a Factory Reset or Reset to Defaults option.
  3. After reset, the device reboots and all settings return to defaults.
  4. You will need to set the Region again before the device will transmit.

Option B: Reconfigure in place

Keep existing settings but review and change each section below. This preserves any custom hardware GPIO settings that may be specific to your board.

Configuration Section 1: USER (Device Identity)

Web Client Path: Config → User

Setting Description Convoy Recommended Value
Long Name Friendly name shown on other devices and the mesh Name each by role: Convoy-Lead, Convoy-Mid, Convoy-Tail, Convoy-4, etc.
Short Name 4-character ID shown on small displays LEAD, MID1, TAIL, CV04, etc.
Is Licensed (HAM) Enables HAM mode: higher TX power but disables encryption OFF — Leave disabled. Convoy needs encryption for private channel.
Is Unmessageable Tells other nodes this device won’t read direct messages OFF — Convoy nodes should be messageable for alerts.

Why it matters for convoy: Clear naming lets you instantly identify which vehicle is which on the mesh, in the Web Client, and in your Python tracker.

Configuration Section 2: DEVICE (Role & Behavior)

Web Client Path: Config → Device

Setting Description Convoy Recommended Value
Role Defines how the device behaves on the mesh See role guide below
Rebroadcast Mode How the device relays other nodes’ packets ALL (default) — Every convoy node should relay packets to extend the chain
Node Info Broadcast Seconds How often the device announces itself 900 (15 min, default) — No need to change
Double Tap as Button Press Accelerometer double-tap acts as button OFF — Not needed for convoy
Disable Triple Click Disables triple-press GPS toggle on the button ON — Prevents accidental GPS disable while driving
LED Heartbeat Disabled Turns off the blinking LED Your preference. OFF saves a tiny bit of power.

Device Role Guide for Convoy Tracking

Role Use For Description
CLIENT (recommended) All convoy vehicles Full functionality: sends, receives, relays messages. GPS active. Screen active. Best for vehicles where someone can see the screen.
CLIENT_MUTE Vehicles that don’t need to relay Sends and receives but does NOT rebroadcast other nodes’ messages. Use only if the convoy is small and every node is in direct range of every other node.
ROUTER DO NOT USE for convoy Designed for fixed infrastructure. No screen, no Bluetooth after initial config. Will break your convoy tracker connection.
TRACKER Unattended asset tracking Sleeps aggressively, wakes only to send position. No message relay. Only use if a vehicle has no driver monitoring the device.
REPEATER DO NOT USE for convoy Retransmits only. No GPS, no messages, no screen. Infrastructure role only.

Convoy recommendation: Set ALL convoy nodes to CLIENT.

Configuration Section 3: LORA (Radio Settings)

Web Client Path: Config → LoRa

This is the most critical section. ALL nodes in the convoy MUST have identical LoRa settings or they cannot communicate.

Setting Description Convoy Recommended Value
Region Legal frequency band for your country US (for United States). MUST be set correctly or device won’t transmit.
Modem Preset Speed vs. range tradeoff LONG_FAST (default) — Best balance for convoy use. Good range with reasonable speed.
Max Hops How many times a message can be relayed 3 (default) — Sufficient for most convoys. Increase to 4-5 only for very long convoys (10+ vehicles).
Transmit Power Radio output power in dBm 0 (use max legal power, default) — Leave at 0 unless you have a specific reason to reduce.
Frequency Slot Specific frequency within the region band 0 (default) — Only change if you experience interference from other Meshtastic users in your area.
TX Enabled Whether the device can transmit ON — Must be on for convoy communication.
Ignore MQTT Ignore messages that came through the internet ON — Convoy tracker should only use direct mesh, not internet-relayed messages.
OK to MQTT Allow your packets to be uploaded to MQTT OFF — Keep convoy positions private, off the internet.

Modem Preset Options (for reference)

Preset Speed Range Best For
SHORT_TURBO Fastest Shortest NOT legal in all regions (500kHz BW)
SHORT_FAST Very Fast Short Urban, close range
SHORT_SLOW Fast Medium-Short —
MEDIUM_FAST Medium-Fast Medium Urban convoys, <2km spacing
MEDIUM_SLOW Medium Medium-Long —
LONG_FAST Medium Long RECOMMENDED for convoy. Default preset.
LONG_MODERATE Slow Longer Extended range convoy if LONG_FAST isn’t enough
LONG_SLOW Very Slow Very Long Maximum range but messages take seconds to send
VERY_LONG_SLOW Slowest Maximum Extreme range, major delay

For convoy tracking, LONG_FAST is the best default. It provides good range between vehicles while keeping message delivery fast enough for real-time tracking. Only switch to LONG_MODERATE or LONG_SLOW if you’re experiencing gaps in the mesh chain at highway convoy distances.

Configuration Section 4: CHANNELS (Communication & Encryption)

Web Client Path: Channels

Channels define who can communicate and how messages are encrypted. For convoy use, you want a private encrypted channel.

Channel 0 (Primary Channel)

Setting Description Convoy Recommended Value
Name Channel identifier (must match on all nodes) CONVOY
PSK (Pre-Shared Key) Encryption key Click Generate to create a random AES256 key. All nodes must have the same PSK.
Downlink Enabled Allow messages from MQTT to this channel OFF — Keep convoy communications local to the mesh only.
Uplink Enabled Send messages from this channel to MQTT OFF — Don’t upload convoy data to the internet.
Position Enabled Share GPS position on this channel ON — This is essential for the convoy tracker.
Position Precision How precise the shared location is Full precision (32) — Convoy tracking needs exact positions, not approximate.

Important Notes on Channels

  • The PSK must match exactly on all convoy nodes. The easiest way: configure Channel 0 on one device, then use the Share/QR/URL feature to copy the exact settings to all other devices.
  • If the radios had a different primary channel from previous use (like the default LongFast), you MUST change it on ALL devices. Mismatched channel names or PSKs mean devices cannot communicate.
  • Position is only automatically broadcast on the lowest-indexed channel with position enabled. Make sure Channel 0 (CONVOY) has position enabled.
  • You can add a secondary public channel (Channel 1) set to LongFast with default PSK if you also want to participate in the public mesh, but this is optional and not needed for convoy tracking.

How to Copy Channel Settings to All Devices

  1. Configure Channel 0 on the first device with name CONVOY and a generated PSK.
  2. In the Web Client Channels page, find the Share or QR code button.
  3. Copy the Channel URL (looks like https://meshtastic.org/e/#...).
  4. Save this URL — it contains all channel and LoRa settings.
  5. Connect to each additional device via Bluetooth.
  6. In Channels, use Import or paste the URL to apply the same settings.
  7. Verify by checking that the Channel name and PSK match on all devices.

Configuration Section 5: POSITION (GPS Settings)

Web Client Path: Config → Position

This is the second most critical section for convoy tracking. These settings control how often and how accurately GPS positions are shared across the mesh.

Setting Description Convoy Recommended Value
GPS Mode Whether GPS hardware is active ENABLED — Must be on for position tracking.
GPS Update Interval How often the device reads GPS (seconds) 15 seconds — Frequent enough for real-time tracking without excessive power draw.
GPS Attempt Time How long to try for a GPS fix each cycle 0 (default: 15 min) — Leave at default unless GPS is slow to lock.
Fixed Position Lock position to a saved coordinate OFF — Convoy vehicles are moving. Only use for a fixed base station.
Smart Broadcast Increase broadcast frequency when moving ON (recommended) — Broadcasts more often while driving, less when stopped. Ideal for convoy.
Smart Broadcast Min Distance Minimum meters traveled before broadcasting 50 meters — Lower than default (100m) for tighter convoy tracking.
Smart Broadcast Min Interval Minimum seconds between broadcasts 15 seconds — Matches GPS update interval.
Broadcast Interval Fixed interval for broadcasting position (when not moving) 30 seconds — More frequent than default (15 min) so the tracker always has recent data.
Position Flags Which data to include in position packets Enable: ALTITUDE, SPEED, HEADING, TIMESTAMP — All useful for convoy tracking.

Understanding GPS Update vs. Broadcast Interval

These are two different things:

  • GPS Update Interval (15 sec): How often the device checks with the GPS chip for a new location. This happens locally on the device.
  • Broadcast Interval (30 sec): How often the device sends its position to the mesh network so other nodes can see it.
  • Smart Broadcast: When enabled, it overrides the broadcast interval when the device is moving — sending updates more frequently based on distance traveled and the smart minimum settings.

For convoy tracking, you want both intervals short so your Python tracker gets fresh data. The tradeoff is more mesh traffic and slightly higher battery usage.

Convoy-Optimized Position Settings Summary

GPS Mode:                    ENABLED
GPS Update Interval:         15 seconds
Fixed Position:              OFF
Smart Broadcast:             ON
Smart Min Distance:          50 meters
Smart Min Interval:          15 seconds
Broadcast Interval:          30 seconds
Position Flags:              ALTITUDE + SPEED + HEADING + TIMESTAMP

Configuration Section 6: POWER (Battery & Sleep)

Web Client Path: Config → Power

Setting Description Convoy Recommended Value
Power Saving Enable aggressive sleep mode OFF — Convoy nodes must stay awake to receive and relay messages in real-time.
Shutdown on Battery Timeout Auto-shutdown when on battery 0 (disabled) — Don’t auto-shutdown during a convoy run.
ADC Multiplier Override Battery voltage calculation Leave at default unless your board reads battery incorrectly.
Wait for Bluetooth Seconds to keep BLE active 0 (always on, default) — Needed for Python tracker BLE connection.
Light Sleep Interval Seconds of idle before light sleep 0 (default) — Let the firmware manage this.

Important for convoy: If these radios were previously configured as routers or trackers, Power Saving may have been enabled. Turn it OFF. Power Saving causes the device to sleep and miss incoming messages, which will create gaps in your convoy tracking data.

Configuration Section 7: DISPLAY (Screen Settings)

Web Client Path: Config → Display

Setting Description Convoy Recommended Value
Screen Timeout Seconds before screen turns off 0 (always on) or 300 (5 min). Useful to see status while driving.
GPS Coordinates Format How coordinates display on screen DMS (degrees/minutes/seconds) or DEC (decimal) — your preference.
Units Imperial or Metric Your preference.
OLED Auto-Detect Display type detection Leave at default unless your screen shows artifacts.

Configuration Section 8: BLUETOOTH (Connection Settings)

Web Client Path: Config → Bluetooth

Setting Description Convoy Recommended Value
Bluetooth Enabled Enable BLE radio ON — Required for Python tracker BLE connection and Web Client configuration.
Pairing Mode How BLE pairing works Random PIN (default) or Fixed PIN — Random is more secure.
Fixed PIN PIN code if using fixed mode Set a PIN you’ll remember (e.g., 123456).

Important: Only ONE BLE client can connect to a Meshtastic device at a time. If your phone is connected via the Meshtastic app, your Python tracker cannot connect via BLE, and vice versa. Disconnect the phone app before running the Python tracker.

Configuration Section 9: NETWORK (WiFi/MQTT)

Web Client Path: Config → Network

Setting Description Convoy Recommended Value
WiFi Enabled Connect device to a WiFi network OFF — Convoy tracker works off-grid via LoRa mesh. No WiFi needed.
MQTT Enabled Connect to an MQTT broker via internet OFF — Keep convoy data on the local mesh only.

Note: If these radios were previously used with MQTT (internet mesh bridging), make sure MQTT is disabled. You don’t want convoy positions being uploaded to a public MQTT server.

Configuration Section 10: TELEMETRY (Environmental Data)

Web Client Path: Modules → Telemetry

Setting Description Convoy Recommended Value
Device Metrics Update Interval How often battery/voltage data is sent 900 (15 min, default) — Useful to monitor battery levels.
Environment Update Interval How often temp/humidity is sent (if sensor attached) 0 (disabled) unless you have environmental sensors.

After Configuration: Verify All Nodes See Each Other

  1. Power on ALL convoy devices.
  2. Connect to any one device via the Web Client.
  3. Go to the Nodes page.
  4. You should see all other convoy devices listed with their names.
  5. Go to Messages and send a test message — confirm it arrives on other devices.
  6. Check the Map or Position view to see if GPS coordinates are coming through.

If a device is missing from the Nodes list, it likely has mismatched LoRa settings or channel configuration. Re-verify steps 8-19 on that device.
