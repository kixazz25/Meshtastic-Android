3 · The rules a new conversation must not break

  • Leader = organizer = a role on the profile. Several orgs per rider. In 2.7 the leader of a ride you create is ALWAYS you.
  • Networks are generated in exactly three places: an org is added · a leader chooses "my own" · a ride asks for a unique one. Each produces a GT id (GT + 9), a 32-byte key, region/preset/hop/role, TX at or below the licence-free limit, and the base version. Immutable — rotation makes a new one.
  • ONE WRITE PATH: profile maintenance creates every rider, org, leader setting and network. Ride creation asks and hands off.
  • Other people exist only as ride data — rides carry the organizer's name, enrollments carry callsigns. No organizer or org records on a receiving tablet.
  • Callsigns may repeat (three Steve S. can ride). Riders are matched by DEVICE: tak_uid, or node_num for radio-only.
  • Four role rules: single-holder leader/middle/tail gunner · release then claim · only a person changes a role (a quiet radio means nothing) · leaving the ride releases it.
  • Only routes travel, distilled to a polyline. Identity is (type, geom_hash), never the hash alone.
  • Nothing is written until Save. No ghosts.
  • Nothing is sent to GroupTrack unless the rider shares — and sharing sends only their ride and their email.
  • ⛔ No OSM-derived data on GroupTrack infrastructure, ever.
  • ⛔ The convoy map is FROZEN. ConvoyScreen.kt is not to be edited. The MENU (ConvoySubMenu, from ui/Main.kt) and the planner are not frozen.

Patches: dated Python to ~/Downloads, idempotent, backs up, aborts without writing on a missing anchor. NEVER reuse a filename. ⚠ Lesson from today: embed Kotlin in a patch script as a RAW literal (r"""…""") — a non-raw literal ate the backslashes and broke the file it wrote.
