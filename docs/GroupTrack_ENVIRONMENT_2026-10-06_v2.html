3. Rules

  • The repository NEVER goes into Google Drive (git + Drive on the same files corrupt each other). Code and docs/ move by git; Drive holds a mirror.
  • Keys stay out of shared folders. Keystore copies exist in iCloud ("GroupTrack Application Keystore") and My Drive ("GroupTrack Application KeyStore"); each machine reads its own local copy through keystore.properties. Expected keystore FILE fingerprint (SHA-256) dd188420089bb1246a62b689158a846984e660c82e548950bf91835ad265ec00; CERTIFICATE SHA-256 37:F0:13:67:D4:54:FD:F0:47:66:6B:A6:D7:6F:5D:E7:26:51:7C:7C:73:82:0F:23:52:D9:8C:51:C7:AB:95:00. No keystore.properties = silent DEBUG signing.
  • One writer per day: the daily processes run on whichever machine is the build device that day, never both; recommit takes a lock in the inbox.
  • Never reuse a filename (Windows "(1)" duplicates) — the daily check flags "(1)" names in the inbox.
  • Every command block in sessions is labelled 💻 MAC or 🖥 PC; long work becomes a script with a one-line run and a log file.
  • Conversation: open on the machine in use; reload (⌘R / F5) when switching — devices do not live-sync.

4. gt_env.sh (GTENV-2026-10-06) — the same names on both machines

Lives in GroupTrack/commands; loaded by every command and by each shell (Mac: one line in ~/.zprofile; PC: one line in ~/.bashrc). Detects the machine by uname and sets: GT_MACHINE (pc|mac), GT_REPO, GT_DRIVE, GT_HOME, GT_INBOX, GT_CMDS, GT_MIRROR, GT_ALLDOCS. Every command is then written once: bash "$GT_CMDS/<command>.sh".

5. Daily start — daily_check (DAILYCHECK-2026-10-06, read-only)

bash "$GT_CMDS/daily_check_v1.sh" on whichever machine you start on: (1) shared folders present; (2) git — branch, this machine vs GitHub, behind (→ git pull), unpushed (→ git push), uncommitted; (3) the shared commands with fingerprints; (4) the inbox — new files, "(1)" duplicates; (5) docs: repository docs/ vs mirror vs AllDocs counts; (6) the signing key present with the expected fingerprint; (7) tools — java (PATH, JAVA_HOME or Android Studio JBR), adb, python. Ends IN SYNC or a numbered list of what is not.

10. Browser downloads and shell differences (10-06)

  • Mac (Safari): downloads land straight in the inbox (or ~/Downloads — the install commands look in both).
  • PC (Edge): Google Drive REMOVES files the browser writes into G: ("no permission to add files") even after granting the user's own profile read+write; cause not understood (Edge SmartScreen's temp file suspected, unproven). PC rule: Edge saves to Downloads; Git Bash moves them into the inbox (Drive accepts that). Recommit to do this move itself on the PC (to build).
  • zsh (Mac) vs Git Bash (PC): quote glob patterns (--include='*.kt'); an unmatched * is an error in zsh; zsh's echo interprets backslashes (\c stops output — it corrupted a bundle check); macOS ships bash 3.2 (no associative arrays) and BSD head/date/stat/ls (no head -n -N, no ls --time-style, no stat -c); timeout absent on the Mac (gtimeout with brew coreutils). Commands use no wildcards where a missing file must STOP the command.
