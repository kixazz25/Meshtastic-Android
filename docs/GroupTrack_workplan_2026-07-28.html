1 · The markComplete refreshMode collision — ONE LINE

DISPLACED TWICE ALREADY ConvoyDownloadQueue:549 branches on entry.refreshMode and silently removes the entry from the queue. But enqueueArea AND enqueueCorridor both set refreshMode = replaceExisting.

So any download submitted with REPLACE ticked is deleted on completion instead of marked COMPLETE — no row, no completedAt, no ETA sample. Strong candidate for BOTH the refresh-never-completes report AND much of the ETA being ~50× long. Fix: branch on downloadType == MAP_SOURCE_REFRESH. Own patch — and any ETA measurement taken before it is untrustworthy.

3 · THE DAY'S BUILD — staged-DB import by area

Fred's architecture (decided 07-27 EOD): a STAGED reference DB on the device; the user draws an area with the existing region tools and pulls only that area's trails into the LIVE spatial DB. The 106,879 trails never land wholesale — which removes the concern about tripling the viewport bbox-scan working set.

What has to be built

  1. A local-file read path. httpGet does URL(urlStr).openConnection() as HttpURLConnection — that cast THROWS on file://. The staged DB is SQLite, so this is not an httpGet variant at all: it is a direct SQLiteDatabase.openDatabase(path, null, OPEN_READONLY) against the staged file.
  2. An area query against the staged DB. Every row already carries min_lat/max_lat/min_lon/max_lon WITH A BBOX INDEX — built for exactly this. Same overlap predicate the viewport queries already use.
  3. Insert into the live DB via the existing path so dedup, ALIAS and trail_properties all behave normally. The staged rows carry wkt in the app's EXACT format and a matching geom_hash, so this is close to a table copy.
  4. Get the staged file onto the device — adb push for testing; a real mechanism later.

Field mapping from the staged schema

osm_id → source_unique_id · name → name (blank takes the 'Not Named' sentinel; ref is already folded into name at subset time) · wkt → geometry · geom_hash → geom_hash · fclass → ? · min/max → bbox columns.

⚠ TWO DECISIONS, both deliberate rather than drifted into: (a) does fclass go to carto_code (drives line colour, and that mapping is duplicated in THREE hand-synchronised places including a FROZEN file), or somewhere else? Leaving carto_code BLANK renders cyan "Unspecified" and touches none of them. (b) Do NOT map motorized_hint onto motorized_allowed without consciously accepting an inference in a legal-access column.
