⛔ The fallback loop — diagnosed, partially fixed

MapSourceManager.ensureInit() tested initialized — a boolean meaning "did init() run in this process" — and on false substituted three hardcoded Esri sources instead of reading the json it could have read. google-hybrid is not among them, so slot 1 rendered nothing.

⭐⭐ Fred's diagnosis, and it is the durable one: "why are we testing init state instead of testing a global variable?" The sources collection IS the state. A flag describing it is a second variable free to disagree — and it did.

⛔ And the 09-10 change cascaded. Removing initialized = true from loadFallback was right in isolation but it was the only thing terminating the fallback path. Fred: "it is never executed again... we are stuck in a loop of init false."

✅ In the tree: ensureInit tests sources.isNotEmpty(), does the real read on a miss, logs at ERROR with the caller stack if that fails.
