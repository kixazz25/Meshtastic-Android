Core rule (governs the whole flow): a route is EITHER an in-process JSON file OR a completed spatial-DB row — never both. The JSON is interim storage holding the SAME data the completed-save consumes (the vertex chain), so a route can be picked up, redisplayed, and editing continued. Graduation writes the DB row and deletes the JSON.
Adaptive principle: Save and Discard are each ONE entry point that opens a CHOICE SCREEN. The current route STATE (new vs resumed · ≥2 pts · draft-on-disk) determines which choices the screen presents. Both behave symmetrically.

Tapping Save opens a full screen. What it offers depends on whether the route is NEW or a RESUMED draft, and on point count. The screen is the disambiguator — one Save entry, state-driven choices.

3 · Adaptive DISCARD screen — same pattern, state-driven

Tapping Discard opens a full screen, symmetric to Save. A NEW route just clears (with a confirm). A RESUMED draft offers roll-back vs delete. Discard NEVER writes except the explicit "delete draft" choice.
Discard route
Leave without saving?
STATE: new route · not saved anywhere
Discard & exit LIVE
Clears the unsaved route from the screen and exits route mode. NO write (nothing was ever persisted).
Keep building
Back to building. Route stays on screen.
DISCARD screen when route is new.
Discard route
This route was opened from a saved draft.
STATE: resumed draft "Bar 10 North"
Roll back to last save SOON
Drop THIS session's edits. The draft JSON on disk is UNTOUCHED — exiting just abandons in-memory changes. (Revert = reload the unchanged file.) NO write.
Delete in-progress route SOON
Remove the draft JSON entirely (prune a dead in-process route). This is the ONLY discard path that writes (a delete).
Keep building
Back to building. No change.
DISCARD screen when route is a resumed draft.

4 · The rules that control the process flow

STATESave tapped → screen offersDiscard tapped → screen offers
NEW, <2 pts Save-completed disabled (need ≥2) · Save in-progress soon · Cancel Discard & exit live · Keep building
NEW, ≥2 pts Save-completed live · Save in-progress soon · Cancel Discard & exit live · Keep building
RESUMED, <2 pts Graduate disabled · Save-changes-to-draft soon · Cancel Roll back soon · Delete in-progress soon · Keep building
RESUMED, ≥2 pts Graduate (+delete draft) soon · Save-changes-to-draft soon · Cancel Roll back soon · Delete in-progress soon · Keep building
The deciding conditions (what the adaptive screens read): currentDraftId (null = NEW · set = RESUMED) · routeVertexCount() ≥ 2 · (implicitly) draft-on-disk = same as RESUMED. These are the ONLY inputs that shape the screens.
