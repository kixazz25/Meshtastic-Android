2 · Design changes for GroupTrack

  1. Apply to a Nucleus = their flow, exactly (F2, F3): read → wait → get (our snapshot / restore point) → apply only the ride's changed fields → wait → get (our verify). Show "the unit is restarting" for up to two minutes; retry on 409.
  2. Send the key as base64: + the ride's key (F4). owner = the rider's callsign (≤ 39, already our rule); owner_short not sent.
  3. The ride's Wi-Fi is the box's own SSID plus the ride's password (F6). network.nucleus.ssid in the ride file stops meaning "the Wi-Fi name"; the tablet learns each box's SSID from the box (or its id). A ride changes only ap.password.
  4. The AP password is the only lock (F5) — make it strong. Replace "one word of 8+ letters" with three words (or 12+ random characters); still readable aloud. Revisit when Natak adds authorization.
  5. GroupTrack is a GUEST on the box (F1, F12). Never PUT a hand-made config: GET, change only our fields, PUT, apply. Save the owner's config before a ride and restore it after. Ask for secondary-channel and extra-AP support so a ride never displaces the owner's use.
  6. Reaching a box: (a) the ride file's password with the box's known SSID; (b) any box over the mesh (F7), IF rides leave the mesh link alone; (c) reset or Ethernet; (d) tailnet with internet.
  7. A third TAK translator for port 257 (F8) — decompress the CoT, read uid/callsign/point/track, and assign through the SAME handleReceivedPosition. Encoding to confirm first (section 4).
  8. An IP translator for the Wi-Fi side, for CoT on the multicast groups — same assignment, TAK-uid key when no node number.
  9. Option: use the Nucleus's radio as the tablet's radio over TCP :4403 (F10) — existing Meshtastic connection code.
  10. The send interval is not in the radio API (F2) — for app-attached radios the app owns cadence (app-sent TAK); for the Nucleus, it is the bridge's.

4 · Port 257 — why, and what it means for us

Why it isn't 72. Meshtastic port numbers 0–63 are core, 64–127 are registered third-party apps, and 256–511 are for private apps. Port 72 (ATAK_PLUGIN) carries Meshtastic's own compact TAKPacket protobuf — PLI and GeoChat only. Port 257 (ATAK_FORWARDER) is the ATAK Forwarder module (Paul Mandal's plugin): it carries whole CoT events, compressed (libcotshrink), so it can move anything ATAK makes — markers, shapes, routes — not just positions. Meshtastic's own V1 path falls back to 257 for everything that isn't PLI or chat. A bridge that forwards arbitrary ATAK traffic naturally uses 257.

What it means. Our port-72 routine will not see positions a Nucleus relays. We need a port-257 translator — decompress, parse the CoT's uid, callsign, point (lat/lon/hae) and track (speed/course), assign through the same function. Messages are bigger (~190 bytes for a PLI), so airtime per report is higher than on 72.

Tooling. The atak-forwarder plugin (an ATAK plugin, Android) is the reference encoder; libcotshrink is its compressor; Meshtastic's Apple app has a V1 ATAK_FORWARDER handler with packet reassembly; a Ruby library decodes 257 with plain zlib. The encoding differs between tools — which is exactly why O3 must be answered before we write the translator.
