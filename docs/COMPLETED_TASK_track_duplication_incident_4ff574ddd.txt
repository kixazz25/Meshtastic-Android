- PROBLEM 1 (permission) — RESOLVED, with a durable GOTCHA:
  Settings -> Clear storage SILENTLY REVOKES the app's ALL FILES ACCESS
  (MANAGE_EXTERNAL_STORAGE special-access grant). Without it the app can't
  read/match the shared folder /sdcard/Documents/my_tracks/ -> import/sync
  can't reconcile -> duplicates + orphans. The original cascade: corrupted
  download_queue.json -> startup ANR -> Clear storage used to fix it -> that
  revoked All-Files AND wiped the spatial DB + tracks.
  RESOLUTION: UNINSTALL + REINSTALL so the grant happens in the setup flow.
  DURABLE LESSON: after ANY data clear, re-grant All-Files (reinstall setup,
  or Settings -> Apps -> Special app access -> All files access ->
  GroupTrack) BEFORE import/sync.

- PROBLEM 2 (different-hash "duplicates") — CLOSED unresolved, cannot
  replicate. What WAS fixed & committed (4ff574ddd): parseGpxTrackPoints used
  a fragile regex  lat="([^"]+)"\s+lon="([^"]+)"  (created 2026-05-22,
  b3368859f) that only matched OUR recorder's exact <trkpt lat="x" lon="y">
  format; external files (onX/Gaia) with a different attribute order parsed
  into a different/empty point set -> different WKT -> different geom_hash ->
  duplicate. FIX = use the same robust trkpt-anchored regex as
  parseGpxTrackPointsFull:
    Regex("""<trkpt\b[^>]*\blat="([^"]+)"[^>]*\blon="([^"]+)"""")
  still returning Pair(lon, lat) (no hash shift for already-correct files);
  no precision/formula/file change. A genuine correctness fix regardless of
  the ghost. BUT it did not fully resolve the reported duplication; after
  extensive tracing the "same ride, two hashes" behavior could not be
  replicated, so it was closed.
  Dedup mechanism confirmed sound: tracks table HAS UNIQUE(geom_hash)
  (verified via .schema); insertTrackToDb uses INSERT OR IGNORE +
  changes()==0. HASHTRACE named-pass showed hash calc is consistent
  (loopHash == resolveHash; same file -> same hash from any filename). The
  scary examples (Bar10 e3/1806 vs 8c/3160) were never proven to be the SAME
  geometry — likely genuinely different recordings (different point counts)
  OR old corrupted-DB artifacts; nobody ever raw-counted the files.
