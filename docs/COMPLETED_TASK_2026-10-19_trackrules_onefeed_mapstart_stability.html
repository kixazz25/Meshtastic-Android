What the logs and the code proved today (evidence, not theory)

  • Sleep 84 s after REC (Droid 2): REC at 11:11:50 in the same app process as the 10:48 recording → the sleep clock still held the earlier time → "no movement for 25 min" at the first points (11:13:14). A recording that ended asleep also left every new point dropped. Fixed by RECSLEEP.
  • The z0 / white screen: every restart that restored the saved frame was followed ~2.5 s later by a zero-size view at 43.06888777, -71.71875 -- exactly my cart rounded to one pixel at ZOOM 0 -- then the whole world. Leaflet's fitBounds works the zoom out from the map's size; called before the map has a size it picks zoom 0. setView (given its zoom) never did this. Offline there are no z0 tiles = white. The saved frames themselves were good (my first theory, a 0,0,0,0 saved frame, was wrong). Only ONE place restores the ride map from the saved file (start-up, ConvoyScreen ~964 + drawPersistedState); FIT uses the database's own bounds. Fixed by FITSIZE + MAPSTARTUP.

  • This morning's Droid 1 Bluetooth stack was stuck: registerApp got no onClientRegistered, scans failed with ApplicationRegistrationFailed; only Bluetooth off/on cleared it. FORGET does remove the radio from Android when it is really connected (Fred).
  • Droid 1's radio GPS mode was found DISABLED (Fred 17:14) -- its position had been frozen at 42.80064,-71.27742 since 09:55. GroupTrack's default writes gpsMode: ENABLED and the setup checks it, so it was not our setup.
