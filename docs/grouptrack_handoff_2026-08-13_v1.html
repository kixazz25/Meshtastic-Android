✅ The day's win — the discard bug, closed

Root cause (proven by reading the branch, not theorizing)

The toolbar Discard button (ConvoyRouteToolbar:196) branches:

if (routeLifecycleState == ROUTE_LS_RESUMED) onDiscardRequested() else onExit()

For a NEW route (ROUTE_LS_NEW) it calls onExit() — which cleared the route from screen and memory but had no deleteDraft. So the per-point autosave had already written Auto Saved In Progress.json to disk, and discard never removed it.

⭐ There was never a "phantom" being recreated on entry. It was one legitimate autosave that discard failed to delete — it looked like it "kept coming back" because it never left. The old comment on onExit assumed "new route = no draft on disk," which was false.

The fix

Added to onExit (ConvoyMapViewerScreen.kt ~1651):

RouteDraftStore.deleteDraft(routeName)
draftListTick++

Same commit also removed the two inline entry-path deleteDraft(UNNAMED) branches bolted on during the earlier DISCARDWINS attempts (they fought the flow). Net 7 insertions, 22 deletions.

Device-verified (Droid 2): create route, drop 5 points, press Discard → route_drafts/ empty, Auto Saved In Progress.json gone. Committed f9652276c, verified in HEAD by grep.
