Storage design v9 — AS BUILT

2026-09-12 · supersedes v7/v8, which were plans. This is what exists and what was measured. Self-contained for a fresh conversation.

The situation

GroupTrack is an Android OHV/convoy trail app (Meshtastic fork, repo C:\\Users\\kixaz\\Meshtastic-Android, branch feature/convoy-event-ride, app id com.grouptrack.android). It kept its data in shared storage at Documents/GroupTrack and Documents/my_tracks, which required MANAGE_EXTERNAL_STORAGE.

2026-09-10: Google rejected the All Files Access declaration — "Access to device storage not required" — and the appeal with it.

⭐ Google's own rejection notice named the way out: the Storage Access Framework. A tree grant the rider gives once, read AND write, no permission, no declaration, no review.

2026-09-12: built, and proven end to end on device with the permission OUT of the manifest.

⚠ EVERY TIMING ESTIMATE IN v7 AND v8 WAS WRONG BY AN ORDER OF MAGNITUDE. Those designs assumed hours for the maps copy and treated it as barely feasible — the space check, the resumability, the per-file loop were all shaped by that. ⭐ It takes four minutes. The design still holds, but the reasons for parts of it do not.

The flow, as built

  1. Gate resolves authority (location only now).
  2. Storage prompt — internal or external, per launch. ⚠ SCAFFOLDING.
  3. Conversion screen, if the record says incomplete. ⛔ Renders INSTEAD of the gate body, so there is no Exit and nothing to cancel with.
    • Restore? ⚠ SCAFFOLDING — undoes a previous run.
    • Select Documents — one broad pick.
    • Maps? — space check, then copy or skip.
    • Move maps out → copy both folders → copy maps → rename sources → write the record.
  4. StartupHousekeeping.run() — and not before, because it calls init(), which OPENS the files the conversion replaces.
  5. Convoy.

⛔ THE CONVERSION OWNS A SCREEN BECAUSE IT NEEDS A RIDER. A SAF tree grant cannot be taken unattended, and housekeeping runs off the main thread where no prompt can happen. That is why it is a gate step and not a housekeeping job.

⛔ The rules that hold it together

One broad pick, two folders read

The grant is on Documents only because that is where both folders can be found. ⛔ It is NOT a licence to read anything else there, and nothing enforces that — it is a discipline in the code. A future change that walks the tree for any other reason is a trust violation however well intentioned.

Inside those two, everything comes

Exclusion list, not inclusion — only maps (handled separately) and *-journal. ⚠ Do not trim the clutter: the three .trails_cleared_* markers look like junk and are not.

⭐ The record IS the flag

One JSON in internal storage. Present and complete means never again. ⛔ A FLAG, NOT A DISK CHECK — Documents is the rider's folder and a stray file named GroupTrack must never re-fire a migration over live data.

⚠ It holds per-item source and destination bytes, the exception TEXT (not just "failed"), the granted URI, and a timestamp per step — which distinguishes a hang from an error.

⭐ "Found nothing" is SUCCESS

A new install grants the tree, the engine looks, there is no GroupTrack — that RESOLVES the conversion. ⛔ Treat it as incomplete and a new rider is asked every launch forever.

Maps: parked, then copied

GroupTrack/maps → Documents/maps via moveDocument, so GroupTrack can be renamed away without taking the tiles. ⛔ Leaving GroupTrack in place instead would "mask the location of where we are retrieving other components — we could run fine until we finish copying maps."

⭐ Space check against the LARGEST SINGLE FILE, not the total, plus a reserve — a device run to nearly full slows badly. SAT.mbtiles is 16 GB in ONE FILE and no loop can split it.

⚠ Copy largest-first, delete each source ONLY after its size matches. ⛔ A source removed on a short write is the one loss this design exists to avoid.

⛔ The renames stand where the deletes go

The field build swaps ONE operation and nothing structural changes. ⭐ And a rename makes a stale path fail LOUDLY — anything still reading Documents/GroupTrack hits a name that does not exist.

Housekeeping — the container

  1. ONE CONTAINER, called once after authority, before any map loads.
  2. SEQUENTIAL, NEVER CONCURRENT.
  3. ⛔ TWO PHASES, init() IS THE BOUNDARY. It OPENS the database files: movers above, content-touchers below. Not a position — a consequence.
  4. ⛔ EVERY JOB GATES ITSELF. No job's condition may stop the stream.
  5. INSERTION REQUIRES IMPACT ANALYSIS.
  6. ⛔ A JOB RETURNS FROM ITSELF, NEVER FROM THE CONTAINER.

⭐⭐ A JOB CANNOT GATE ITSELF UNTIL IT IS A FUNCTION. With the body inline, "return when there is nothing to do" and "return from the container" are the same statement.

⭐ NO RELEASE OR UPDATE SECTIONS. Every job runs every launch and decides for itself: once ever → a marker it writes; once per release → a marker whose NAME changes; always → nothing.

⭐ Things learned that outlive this work

  • Grep for the destination, not the API. Two APIs reach Documents: getExternalStorageDirectory() and getExternalStoragePublicDirectory(DIRECTORY_DOCUMENTS). A sweep on one found 13 and missed 23.
  • ⭐⭐ The cross-reference finds what grep cannot. migrateTiles() was a live landmine whose dangerous line reads getExternalFilesDir — it LOOKS like the destination, not a problem. A function index of everything doing file work is what surfaced it.
  • Compose reacts to State, not to facts. An early return does not unschedule an effect already declared; a plain field set on a singleton triggers no recomposition.
  • onDismiss() disposes the launcher. A menu item that waits for a result must not close the sheet that owns it.
  • Search by label, not by filename. "Convoy radio menu" matched ConvoyFieldRadioScreen — a parked V3 screen nothing navigates to. The real sheet was found by its visible title in one grep.
  • ⭐ /sdcard/Android/data/<pkg>/files/ IS readable by the adb shell. Two days were spent designing around a diagnostic blackout that does not exist for development. The in-app record still earns its place for a RIDER's device.
