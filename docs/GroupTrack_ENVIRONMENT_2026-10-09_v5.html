3. Rules

  • The repository NEVER goes into Google Drive (git + Drive on the same files corrupt each other). Code and docs/ move by git; Drive holds a mirror.
  • Keys stay out of shared folders. Keystore copies exist in iCloud ("GroupTrack Application Keystore") and My Drive ("GroupTrack Application KeyStore"); each machine reads its own local copy through keystore.properties. Expected keystore FILE fingerprint (SHA-256) dd188420089bb1246a62b689158a846984e660c82e548950bf91835ad265ec00; CERTIFICATE SHA-256 37:F0:13:67:D4:54:FD:F0:47:66:6B:A6:D7:6F:5D:E7:26:51:7C:7C:73:82:0F:23:52:D9:8C:51:C7:AB:95:00. No keystore.properties = silent DEBUG signing.
  • One writer per day: the daily processes run on whichever machine is the build device that day, never both; recommit takes a lock in the inbox.
  • Never reuse a filename (Windows "(1)" duplicates) — the daily check flags "(1)" names in the inbox.
  • Every command block in sessions is labelled 💻 MAC or 🖥 PC; long work becomes a script with a one-line run and a log file.
  • Conversation: open on the machine in use; reload (⌘R / F5) when switching — devices do not live-sync.

4. gt_env.sh (GTENV-2026-10-06) — the same names on both machines

Lives in GroupTrack/commands; loaded by every command and by each shell (Mac: one line in ~/.zprofile; PC: one line in ~/.bashrc). Detects the machine by uname and sets: GT_MACHINE (pc|mac), GT_REPO, GT_DRIVE, GT_HOME, GT_INBOX, GT_CMDS, GT_MIRROR, GT_ALLDOCS. Every command is then written once: bash "$GT_CMDS/<command>.sh".

5. Daily start — daily_check (DAILYCHECK-2026-10-06, read-only)

bash "$GT_CMDS/daily_check_v1.sh" on whichever machine you start on: (1) shared folders present; (2) git — branch, this machine vs GitHub, behind (→ git pull), unpushed (→ git push), uncommitted; (3) the shared commands with fingerprints; (4) the inbox — new files, "(1)" duplicates; (5) docs: repository docs/ vs mirror vs AllDocs counts; (6) the signing key present with the expected fingerprint; (7) tools — java (PATH, JAVA_HOME or Android Studio JBR), adb, python. Ends IN SYNC or a numbered list of what is not.

10. Browser downloads and shell differences (10-06)

  • Mac (Safari): downloads land straight in the inbox (or ~/Downloads — the install commands look in both).
  • PC (Edge): Google Drive REMOVES files the browser writes into G: ("no permission to add files") even after granting the user's own profile read+write; cause not understood (Edge SmartScreen's temp file suspected, unproven). PC rule: Edge saves to Downloads; Git Bash moves them into the inbox (Drive accepts that). Recommit to do this move itself on the PC (to build).
  • zsh (Mac) vs Git Bash (PC): quote glob patterns (--include='*.kt'); an unmatched * is an error in zsh; zsh's echo interprets backslashes (\c stops output — it corrupted a bundle check); macOS ships bash 3.2 (no associative arrays) and BSD head/date/stat/ls (no head -n -N, no ls --time-style, no stat -c); timeout absent on the Mac (gtimeout with brew coreutils). Commands use no wildcards where a missing file must STOP the command.

17. Working rules learned 10-08, and proposals recorded (not adopted)

  • Drive drops the executable bit on shared commands — run them as bash "$GT_CMDS/…" on both machines ("permission denied" otherwise).
  • deploy.sh says "build not found" while Drive is still filling the folder — wait a minute and re-run (should say "still syncing" — proposed).
  • zsh does not split $VAR into words (bash does): tar … $F treated a list as one name — name files explicitly.
  • Commit messages in plain characters — brackets, parentheses or < > in a pasted -m "…" failed to parse on the Mac (likely curly quotes from the paste).
  • Text pasted while a build runs is queued and runs (or fails to parse) when it ends — wait for the prompt.
  • Proposed, NOT adopted (no tooling changes until the tablets load from the Mac, except Fred's v23 step): recommit refuses any file over 50 MB and keeps device logs out of git; recommit stops loudly with "PUSH REJECTED" instead of finishing quietly; a plan for GroupTrack_AllDocs.txt (57 MB, GitHub warns at 50, rejects at 100); deploy.sh "still syncing".

18. Reading what is on a tablet (10-09) — the database, the map settings, the map page

  • Git Bash rewrites device paths (/sdcard/… becomes C:/Program Files/Git/sdcard/…). Start every device path with // and quote the whole shell command: adb -s <serial> shell "find //sdcard/Android/data/com.grouptrack.android -name 'grouptrack_*.db'".
  • The two databases live in //sdcard/Android/data/com.grouptrack.android/files/GroupTrack/: grouptrack_spatial.db (trails, tracks, routes, waypoints — what the map queries) and grouptrack_data.db (trail_properties, aliases — the detail card). Droid 1 lets adb pull them (adb -s 8624SBCEDF00001789 pull //sdcard/…/grouptrack_spatial.db ~/Downloads/d1_spatial_<date>.db, ~350 MB / 10 s); Droid 2 refused (Permission denied). run-as does not work — release-signed builds are not debuggable.
  • The rider's map settings: map_keys.json in the same folder (land, use, the off list, style) — read it FIRST when trails look "missing".
  • Logs that matter (PC, device plugged in): adb -s <serial> logcat -d -s SpatialDisplay MapJS ConvoyJS RiderTrails | tail -40. TRACE Trails: raw= items= json= state= = what the query returned and sent; TRAILDRAW Trails: sent N -> page "ok N" = what the page holds (release i); MapJS/ConvoyJS = the pages' own errors (INFO since release i — DEBUG lines are stripped from release builds); RiderTrails = ADD TRAILS FROM TRACKS (added / unchanged / removed).
  • chrome://inspect (PC Chrome, tablet on USB) shows the live map page (layers, canvas, console) — ONLY on a 2.7b build carrying WEBDEBUG (66d6f0a82). Never on the release branch; remove before 2.7b ships.
  • Read-only PC tools (Downloads): gt_extract_area_2026-10-09_v2.py <spatial.db> "<track name>" (one track + every trail around it → JSON for off-device tests) · gt_jsoncheck_2026-10-09.py <spatial.db> <data.db> (trails whose map entry would break a batch) · gt_drawcheck_2026-10-09.py (rider bboxes + the map's own query).

19. Working rules learned 10-09

  • A tablet will not install an older version code (INSTALL_FAILED_VERSION_DOWNGRADE, and -d does not help on a non-debuggable build). The tablets run 2.7b builds (higher version code), so a release-branch change is TESTED on a 2.7b build (merge, same code) and RELEASED from the release branch.
  • zsh: a word that starts with = is a command lookup — echo ==== fails; quote it. git opens a pager on long output — git --no-pager …, or q to leave it.
  • Downloads on the Mac land in ~/Downloads, not the Drive inbox — run a patch as python3 ~/Downloads/patch_….py, or move it first.
  • An AAB content check after every release build: unzip -p <aab> 'base/dex/*.dex' | LC_ALL=C grep -a -c -e '<string only this release has>' must be ≥ 1 (check_build_v2's 15 markers do not cover new work).
