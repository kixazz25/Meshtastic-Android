The .convoy ride file — format 3

2026-09-22 · v1 · replaces ConvoyEventConfig's JSON (format 2, radio-first).

A ride is a package of map, route and waypoint data with a leader and a date — and it is useful with no network at all. The file is self-contained: emailed, opened offline, ridden, forwarded. The network is a property the ride may carry so the group's radios can find each other.

1 · The sections

SectionPresenceContents
kind, formatVersionrequired"grouptrack.ride" and 3. A hard cut — a 2.6 tablet does not read a v3 file and says so plainly rather than half-importing it.
riderequiredrideId (UUID — the identity between tablets), name, date, startTime, description, zipCode, createdAt.
leaderrequiredname, callsign, orgName (empty for an independent leader). No user id, no phone. email only if the leader ticks "let riders reply to me" at send time.
networkoptionalAbsent when the leader has no radios — the ride still works. id (the GT id), baseVersion, and a block per transport: mesh and nucleus. Both are written whenever a network exists.
rideDataoptionalOne GPX document carrying the route as <rte> and the waypoints as <wpt>, plus routeGeomHash, routeName and routeNotes (JSON — GroupTrack's own, no GPX equivalent).
mapoptionalThe area the ride needs: north/south/east/west and maxZoom, so the receiver can fetch tiles. No tiles travel in the file.

3 · The rules

RuleWhy
⛔ Nothing OSM-derived travelsThe leader's own drawn route and their waypoints are theirs to send. The trail layer underneath is not — and the receiver already has its own copy.
Unknown sections are KEPTOn import, a section this build does not recognise is stored with the ride, so a forwarded file stays complete for the next rider.
Whole sections are optional, fields inside them are notIf network is present it is complete. That keeps the reader simple: check the section, then trust it.
The route travels as its drawn lineThe polyline the leader drew (the stored LINESTRING), not the recipe that built it. The receiver draws exactly what the leader drew, with no trail network required. geom_hash rides along so import dedupes without re-hashing.
One GPX, both kindsRoute as <rte>, waypoints as <wpt>. Recorded tracks, if they ever travel, stay <trk> — the distinction is free and worth keeping.
The ride id is the identityRe-importing the same file updates that ride rather than making a second one. A leader can send a corrected ride and riders simply take it.

4 · What format 2 carried and format 3 does not

DroppedWhy
hardwareId as the primary keyThe ride is not owned by a radio. rideId is the identity; the radio is a detail of one rider's kit.
deviceId, hardwareModel, firmwareVersionThe receiver's own radio is what matters, not the leader's.
organizerUserId, organizerPhone, organizerFirstName/LastNameA receiving tablet needs a name and callsign to show who leads. Nothing else about the leader is anyone's business.
Flat LoRa fields at the top levelThey move inside network.mesh, so a ride with no radios is expressible at all.
expirationDate (30 days past the ride)DECIDE: keep as a tidy-up hint, or drop and let rides age in the list? V2 set it and nothing enforced it.

5 · The nucleus block — a placeholder, on purpose

Written empty until Natak's API settles. Named nucleus rather than ip because it is Natak's hardware with its own fields; another IP transport would get its own block rather than fight over one.

What the fields are for: cotPort — CoT v0 XML goes to the box on some port (Nathan, 09-22: plain CoT XML is the format; the SDK handles compression). tailnet — every Nucleus runs Tailscale, so a leader could push a ride straight to the group's boxes instead of emailing. Empty means email, which stays the universal path for mesh-only riders and anyone offline at a trailhead.

Three answers owed by Natak: which port and transport CoT arrives on · whether a Nucleus is already joined to a tailnet when it ships · whether the config API sets SSID and password, or they come preset. The last one decides whether GroupTrack can generate the IP half of a network itself.

6 · Still to decide

  1. The leader's email — off by default, ticked at send time to let riders reply? Or never?
  2. Expiration — keep the 30-day date as a tidy-up hint, or drop it?
  3. Zipped or plain — a zipped .convoy is one attachment and much smaller with GPX inside; plain is readable in a text editor.
